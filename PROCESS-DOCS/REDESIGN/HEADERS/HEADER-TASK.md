# HEADER-TASK: универсальная шапка экрана

Задание для Claude Code. Три этапа, строго по порядку. После каждого этапа —
остановка и проверка списком в конце этапа. Не начинать следующий, пока текущий
не проходит проверки.

Референс поведения: `ugolok-header.html` (рабочий прототип, приложен). Из него
переносится **раскладка и поведение**, не оформление: цвета и шрифты в прототипе
свои, в проекте берутся существующие OKLCH-токены.

---

## Инварианты (нарушение любого = переделка этапа)

1. **Функциональность не меняется.** Все существующие обработчики, пропсы,
   маршруты, состояния сохраняются. Это работа по вёрстке и структуре, не по логике.
2. **Никаких медиазапросов по окну для шапки.** Только `@container`. Шапка обязана
   вести себя одинаково в полную ширину и внутри узкой панели двухпанельной раскладки.
3. **Никаких флагов видимости** вида `showBack` / `showAvatar` / `showTabs`.
   Зона рисуется тогда и только тогда, когда в неё передано содержимое.
4. **Никакой фиксированной высоты шапки.** Ни `--header-h`, ни `height` на
   `.section-header`. Высота меняется при перекладывании — это часть замысла.
5. Не добавлять зависимостей. Не трогать сборку.

## Этап 1. Вынести медиа-срезы из шапки в ленту

**Зачем:** сейчас в слот `slices` компонента `Screen` кладутся две разные по смыслу
вещи — разделы экрана (вкладки канала) и срез списка по типу вложения. В канале на
вкладке «Чат» они понадобятся одновременно, и один слот их не вместит. Разделы
принадлежат экрану, срез — списку внутри раздела.

**Файлы:** `src/ui/screens/chat.jsx`, `src/ui/screens/channel.jsx`,
`src/ui/components/screen.jsx`.

**Что сделать:**

- В `chat.jsx` (`ChatWindow`, вызов `<Screen>` ~592-614) убрать `slices={<MediaButtons …/>}`.
  `MediaButtons` рендерится теперь первым элементом внутри `feed`, липко к его верху.
- То же в `channel.jsx`, если `MediaButtons` там используется.
- Слот `slices` в `Screen` остаётся, но его назначение сужается: **только навигация
  по разделам экрана**. Отразить это комментарием в сигнатуре `Screen`.
- Полоса срезов получает фон ленты, а не шапки, и собственную нижнюю границу.

```css
.media-cuts{
  position: sticky;
  top: 0;
  z-index: 2;
  display: flex;
  gap: 6px;
  overflow-x: auto;
  scrollbar-width: none;
  padding: 8px 10px;
  background: var(--surface-feed);
  border-bottom: 1px solid var(--border);
}
.media-cuts::-webkit-scrollbar{ display: none }

.media-cut{
  flex: 0 0 auto;
  min-height: 32px;
  padding: 0 12px;
  border: 1px solid var(--border);
  border-radius: 16px;
  white-space: nowrap;
}
.media-cut[aria-pressed="true"]{ /* заливка акцентом, текст — контрастный */ }

.media-cut--all{
  position: sticky;
  left: 0;
  z-index: 1;
  background: var(--surface-feed);
}
```

- Первый чип — «Все», он же сброс, закреплён слева (`position: sticky; left: 0`),
  чтобы выход из фильтрации не уезжал при горизонтальной прокрутке.
- Срез **однозначно одиночный**: нажатие на чип снимает предыдущий.
  Состояние — `aria-pressed`, а не класс `.active`.
- Под полосой — строка состояния, видимая только когда выбрано не «Все»:
  `«Изображения · 42»` плюс кнопка `«Показать все»`. Без неё включённый срез
  выглядит как пропавшие сообщения.
- **При каждом входе в чат срез сбрасывается на «Все».** Не сохранять его между
  открытиями экрана — иначе человек не увидит новых текстовых сообщений и решит,
  что чат сломан.

**Проверки этапа 1:**
- [ ] Шапка чата стала одноуровневой, `.slices-zone` в чате не рендерится вообще.
- [ ] Полоса срезов прокручивается пальцем, «Все» остаётся видимым.
- [ ] Выбор среза меняет ленту так же, как до правки; строка состояния показывает счёт.
- [ ] Повторное открытие чата возвращает «Все».

## Этап 2. Шапка на grid (главный этап)

**Файлы:** `src/ui/components/screen.jsx` и его стили.

### 2.1 Структура разметки

`.header-actions` переименовать в `.section-header__row` — сейчас имя обещает
кнопки, а содержит всю верхнюю строку. Внутри `<header class="section-header">`
ровно четыре зоны, каждая рендерится только при наличии содержимого:

```jsx
<header class="section-header">
  {onBack && <button class="header-back" …/>}
  {lead && <div class="header-lead">{lead}</div>}
  <div class="screen-title">
    <h1 class="screen-title__text">{title}</h1>
    {subtitle && <p class="screen-title__sub">{subtitle}</p>}
  </div>
  {actions && <div class="header-actions">{actions}</div>}
  {headerExtra}
</header>
```

**Важно:** `.screen-title` рендерится ВСЕГДА, а не только при наличии `subtitle`,
как сейчас. Иначе один и тот же заголовок живёт в двух разных структурах и
`grid-area` приходится описывать дважды.

### 2.2 Раскладка

```css
.section-header{
  container-type: inline-size;
  display: grid;
  grid-template-areas: "back lead ident actions";
  grid-template-columns: auto auto minmax(0, 1fr) auto;
  align-items: center;
  background: var(--surface-header);
  border-bottom: 1px solid var(--border);
}

.section-header > *{ padding-inline: 4px }
.section-header > :first-child{ padding-inline-start: 6px }
.section-header > :last-child{ padding-inline-end: 6px }

.header-back   { grid-area: back }
.header-lead   { grid-area: lead; display: flex; align-items: center }
.screen-title  { grid-area: ident; min-width: 0; padding-block: 8px }
.header-actions{ grid-area: actions; display: flex; align-items: center; justify-self: end }

.screen-title__text{
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
.screen-title__sub{
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
  color: var(--text-secondary);
}

@container (width < 30rem){
  .section-header{
    grid-template-areas:
      "back lead actions"
      "ident ident ident";
    grid-template-columns: auto auto minmax(0, 1fr);
  }
  .screen-title{ padding-block: 0 10px; padding-inline-start: 10px }
  .screen-title__text{ white-space: normal }   /* заголовок получает вторую строку */
  .header-actions .btn-label{ display: none }  /* остаются только иконки */
}
```

**Три места, которые нельзя «упростить»:**

- `minmax(0, 1fr)` на колонке заголовка. Без нуля в `minmax` элемент грида не
  сжимается меньше своего содержимого, и длинное имя выталкивает кнопки за край.
  Это причина текущего переполнения.
- Отсутствие `column-gap`. Зазоры сделаны отступами зон намеренно: `gap` ставится
  между дорожками и сохраняется, когда дорожка схлопнулась в ноль. На экранах без
  кнопки «назад» (профиль, настройки) заголовок иначе уедет вправо на пустоту.
- `container-type: inline-size` на самой `.section-header`, а не на родителе.

### 2.3 Кнопки

Видимый размер иконки — 20px, **зона нажатия всегда 44px** по обеим сторонам:

```css
.section-header .btn{
  min-height: 44px;
  min-width: 44px;
  display: inline-flex;
  align-items: center;
  justify-content: center;
  gap: 7px;
}
```

Добор до 44 делается `min-height` кнопки, не увеличением иконки и не отступами ленты.
Видимый фокус (`:focus-visible`) обязателен — сейчас его нет.

**Проверки этапа 2** (гонять изменением ширины окна и ширины панели отдельно):
- [ ] На ширине контейнера < 30rem заголовок переезжает на вторую строку целиком,
      без многоточия; кнопки остаются в верхней строке справа.
- [ ] Имя «Уголок: разработка и планы» ни на одной ширине не выталкивает кнопки.

- [ ] `files.jsx` с длинным путём: заголовок обрезается только на широком экране,

- [ ] Все 13 экранов из списка ниже открываются без визуальных регрессий.

## Этап 3. Разделы канала

**Файл:** `src/ui/screens/channel.jsx` (`ChannelDetail`, `<Screen>` ~488-517).

Сейчас в `slices` четыре вкладки: Посты, Чат, Модерация, Настройки. Разделить по
частоте использования:

- В полосе разделов остаются **«Посты» и «Чат»** — то, что открывают ежедневно.
- **«Модерация» и «Настройки»** уходят в меню под кнопкой-шестернёй в `actions`.
  Они доступны только владельцу и модератору, значит и в шапке им не место.
- На «Чате» показывать счётчик непрочитанного бейджем внутри вкладки.

При двух вкладках полоса помещается на 320px без прокрутки — горизонтальное
перетаскивание разделов не требуется вовсе, и реализовывать его не надо.

Разметка вкладки: `role="tab"` + `aria-selected`, активная помечена нижней
границей 2px акцентным цветом. Не `<a>`, если переключение не меняет маршрут.

**Проверки этапа 3:**
- [ ] На 320px обе вкладки видны целиком, полоса не прокручивается.
- [ ] Модерация и настройки открываются из шестерни, права доступа не изменились.
- [ ] Счётчик непрочитанного обновляется как раньше.

## Чего не делать

- Не заводить `switch` по маршруту внутри `Screen`. Компонент не должен знать про
  конкретные экраны — содержимое приходит через слоты.
- Не заменять слоты набором булевых пропсов.
- Не добавлять `display: none` на зоны — пустая зона не рендерится вовсе.
- Не вводить свайп по содержимому для переключения разделов: в канале горизонтальный
  жест по сообщению уже занят ответом.
- Не менять цвета и типографику. Все значения — из существующих токенов; если
  нужного токена нет, добавить в общий файл токенов, а не хардкодить в компоненте.
