# ТЗ: экран «Хранилище» (Файлы) — вариант Б, полоса режима

**Куда положить файл:** `PROCESS-DOCS/REDESIGN/FILES/FILES-REDESIGN.md`
**Референс-макет:** `files-B.html` (в сборку не идёт)
**Словарь оформительского слоя:** `PROCESS-DOCS/MOLECULES.md`
**Регламент раскладки:** `PROCESS-DOCS/REGLAMENT.md`
**Статус:** к исполнению. §13 закрыт ответами пользователя (2026-08-25).

Это ТЗ для оркестратора, не дословный дамп `files.jsx`. Логика дерева,
загрузки, шаринга, undo, drag-and-drop, виртуализации списка **не
переписывается** — меняются шапка, срезы, вид списка/плиток и то, что
делает клик по типу.

---

## 0. Зачем

На живом экране сейчас полный расколбас:

1. Заголовок «Файлы» дублируется: `Screen` рисует `<h1>` из `nav.files`,
   а в контенте крошки снова начинаются с корня с тем же смыслом.
2. Корзина сидит в строке крошек после `<span class="grow" />` и улетает
   в правый верх через пустоту. Так никто не делает; в макете это прямо
   названо найденным дефектом.
3. Единственный вид — список. Для фото это худший из возможных.
4. Всё, что не картинка с готовой миниатюрой, получает одну и ту же
   `IconFileText` — mp3, mp4 и pdf выглядят одинаково.
5. Главная ошибка продукта: кнопки «Аудио» / «Видео» / «Изображения»
   (и «Файлы»/`other`) **открывают медиа-оверлей со слайдером**. Это не
   фильтр. Человек не может просто посмотреть «только картинки в этой
   папке». Оверлей можно свернуть в минибар — но он запускается не с
   того места.

Макет «вариант Б» чинит раскладку и вводит **полосу режима**: она
появляется только при активном фильтре по типу и вслух отвечает на
вопрос «почему список вдруг стал плитками».

## 1. Закрытые решения (пользователь, эта сессия)

| Тема | Решение |
|---|---|
| Кнопки типов в шапке срезов | **Фильтры**, не запуск оверлея |
| Вид после фильтра | Меняется вместе с типом (см. §3.2) |
| Память вида | Только сессия, **по типу**. Reload → всегда список и фильтр «Всё» |
| Сброс фильтра | Обязателен: чип «Всё» **и** крестик полосы режима. Иначе из «только аудио» (папки спрятаны) нельзя вернуться |
| Папки в типовом фильтре | Прячутся |
| Чип с нулём | Прятать (не отвлекать на то, чего нет). «Всё» виден всегда |
| Документы, пачка | Кнопки слайдера нет |
| Документ, один клик | Не оверлей, а **маленькая модалка**: сведения + «Скачать» (§3.7) |
| Клик по медиа при фильтре | Оверлей **со всей текущей выборкой**, листать соседей. «Слушать/смотреть подряд» — **с начала пачки** (position 0) |
| Иконки `other` | pdf / xls(x) / doc(x) своими глифами, остальное — `file-text` |
| «⋯» на плитке | Да, то же меню действий, что у строки |
| «Полученные» | Решение оркестратора §4.2: toggle в шапке |

Кнопки типов на **других** экранах (`MediaButtons` в чате/канале) этим
ТЗ **не трогаются**: там «открыть слайдер по классу» — другой сценарий,
он остаётся.

## 3. Модель фильтра и вида

### 3.1. Состояние (только экран, только сессия)

В `files.jsx` (не в `ui-settings.js`):

```js
// typeFilter: "all" | "image" | "video" | "audio" | "other"
// layout: "list" | "grid"
```

Плюс словарь сессионных override'ов вида:

```js
// viewOverride: { [typeFilter]: "list" | "grid" }
```

Reload / размонтирование экрана всё забывает.

### 3.2. Рекомендованный вид + сессия + reload

| Фильтр | Рекомендация при первом входе в тип за сессию |
|---|---|
| `all` | список |
| `image` | плитки |
| `video` | плитки |
| `audio` | список |
| `other` (документы) | список |

Правило (закрыто пользователем):

1. **Старт экрана и любой reload** → `typeFilter = "all"`, `layout = "list"`,
   `viewOverride = {}`. Человек всегда оказывается в списке без фильтра.
2. Переключателя вида при «Всё» **нет** (нет полосы режима).
3. Клик по типу → если в `viewOverride` ещё нет записи для этого типа,
   ставится рекомендация из таблицы. Полоса режима называет тип вслух.
4. Кнопки списка/плитки пишут `viewOverride[typeFilter]` и меняют
   `layout`. Выбор держится, пока жива вкладка.
5. Уход на другой тип и возврат: если override есть — он, иначе снова
   рекомендация.
6. **Сброс фильтра** (два равноправных действия, оба обязательны):
   - чип «Всё»;
   - крестик полосы режима (`files.clearTypeFilterAria`).
   Оба ставят `typeFilter = "all"`, `layout = "list"`. Override других
   типов не стирают (пока сессия жива).
7. После reload пункт 1 важнее рекомендации: даже если в прошлой сессии
   картинки смотрели списком, новая сессия начинается с «Всё» + список;
   первый клик «Изображения» снова даст плитки (нет override).

### 3.3. Что показывает список при фильтре

- `all`: живые дети папки как сейчас (папки + файлы), плюс поиск по имени.
- `image` / `video` / `audio` / `other`: **только файлы** этого `classOf(mime)`.
  Папки скрываются (в кадре «Аудио» макета папок нет).
- Поиск по имени **складывается** с типовым фильтром (И): сначала тип,
  потом подстрока имени. Существующий `filterEntries` остаётся; тип —
  отдельный предикат рядом, не замена поиска.
- Файлы без `mime` (`null`, ещё не backfill) в типовом фильтре **не
  попадают** ни в один класс, кроме «Всё». Не угадывать класс по
  расширению имени.

Пустая выборка — существующая заглушка `files.folderEmpty` (или новый
ключ «нет файлов этого типа», см. §10), не падение.

### 3.4. Полоса режима (`.mode-bar`)

Рендерится **только** если `typeFilter !== "all"`.

Состав слева направо (макет):

1. Иконка типа + название («Аудио» / «Изображения» / …).
2. Счётчик: `N файла(ов)`. Длительность («1 ч 06 мин») **не показывать**:
   в манифесте/узле длительности нет, выдумывать запрещено.
3. `grow`.
4. Кнопка слайдера — **только** для `image` / `video` / `audio` и только
   если в выборке есть хотя бы один файл. Для `other` кнопки нет.
5. Сегмент вида `.seg.view-toggle`: список / плитки.
6. Крестик «показать всё» → `typeFilter = "all"`.

Кнопка слайдера **не** зовёт старый `openFolderMediaClass` «как было»
(тот собирал всю папку и прыгал к первому файла класса). Новый путь:

- плейлист = **видимая выборка** (тип ∩ поиск), только файлы
  `image`/`video`/`audio`, в том же порядке, что на экране;
- «Слушать/смотреть подряд» → `openMedia({ refs, position: 0 })` —
  **с начала пачки**;
- оверлей и минибар — существующие, не переписывать.

Подписи:

- audio → «Слушать подряд»
- video → «Смотреть подряд»
- image → «Смотреть»

### 3.5. Клик по элементу в списке/плитке

| Элемент | Действие |
|---|---|
| Папка | `openFolder` |
| Файл `image` / `video` / `audio` | оверлей со **всей текущей выборкой** медиа (тип ∩ поиск, без папок и без `other`), `position` = индекс кликнутого. Листать соседей можно. Отличается от «подряд» только стартовой позицией |
| Файл `other` | **не** `openMedia`. Маленькая модалка §3.7 |

Чип типа оверлей не открывает.

Если фильтр «Всё» и клик по фото: выборка = все видимые `image`/`video`/`audio`
текущей папки (после поиска), в порядке списка. Документы и папки в
плейлист не попадают.

### 3.6. Срезы (`.slices-zone`)

Порядок: `Всё` · `Изображения` · `Видео` · `Аудио` · `Документы`.

- «Всё» **всегда** на месте (это и есть сброс, плюс крестик в полосе).
- Остальные чипы — **только если count > 0**. Ноль не показывать.
- Активный — `slice--on`.
- Число — `slice__n`. «Всё» — число живых детей папки (папки+файлы).
  Тип — `classCount` текущей папки (не после поиска: счётчик говорит
  «сколько этого типа в папке», поиск режет уже список).

Новый компонент `TypeFilterBar` только для `files.jsx`.
`MediaButtons` в чате/канале не трогать.

`openFolderMediaClass` из срезов удаляется. Спиннер `mediaButtonsBusy` —
на кнопке слайдера в полосе.

### 3.7. Модалка сведений о документе

Не медиа-оверлей и не `file-viewer.jsx` внутри него. Отдельный маленький
`role="dialog"` на экране файлов, по образцу уже существующего
`shareDialog` в `files.jsx` (~строка 896): подложка, закрытие по крестику,
Escape, клик по фону.

Содержимое:

- иконка по mime (§5.1);
- имя файла;
- человекочитаемый тип (PDF / таблица / документ / mime);
- размер через существующий `formatFileSize` (как в `file-viewer.jsx`);
- кнопка «Скачать».

«Скачать» — тот же приём, что `file-viewer.jsx`: `acquireMediaUrl` →
`<a download>` или программный клик по object-URL. Байты не читать в
оверлей заранее. Ошибка сети — `role="alert"` текстом, модалку не
закрывать молча.

Не листать «следующий документ». Один файл — одно окно.

## 4. Раскладка шапки (макет)

`Screen` остаётся каркасом.

### 4.1. `<h1>`

Имя **текущей папки** (последняя крошка), не константа `nav.files`.
В корне — подпись корня (сейчас это то, что уже лежит в `breadcrumbPath[0].name`;
если это «Файлы», так и будет; не заводить второй заголовок в контенте).

Дубль «Файлы сверху и над фильтром» уходит, потому что второго заголовка
в `.files-shell` нет.

### 4.2. Действия шапки (`.action-buttons`)

Порядок как в макете, `view === "own"`:

1. «Загрузить» — тот же `triggerFileUpload` (иконка upload из Phosphor,
   не paperclip).
2. «Папка» — тот же `setNewFolderOpen` (иконка folder-plus / folder).
3. «Полученные» — **toggle**. `aria-pressed={view === "mounts"}`.
   Повторный клик возвращает в `"own"`. Число `slice__n` только если
   `activeMounts.length > 0` (ноль не рисуем, саму кнопку оставляем —
   иначе раздел не найти).
4. Корзина — `icon-btn`, `aria-label` = `files.trashButton`,
   `openFolder(TRASH_ID)`. **Не** в крошках. Когда уже в корзине или
   `view === "mounts"` — не показывать.

В режиме `"mounts"`: срезы типов и полоса режима **скрыты** (это чужие
папки, не фильтр своей). Загрузить / новая папка / корзина — только
`"own"`, как сейчас. Внутри открытой доли существующая «К списку долей»
остаётся.

Paste / Undo — в ту же группу, `btn--ghost`, если буфер/флаг живы.
Вкладка «Мои файлы» из `actions` **убирается**.

### 4.3. Крошки

Как сейчас по данным, но:

- убрать `<span class="grow" />`;
- убрать кнопку корзины отсюда;
- разделитель — существующий `IconChevronRight`.

### 4.4. Поиск

Существующее `.file-search-field`. Плейсхолдер макета: «Поиск в этой
папке» (ключ можно оставить `files.filterPlaceholder`, сменив строку).

## 5. Список и плитки

### 5.1. Список (`.file-row-list`)

Существующая строка почти как есть:

иконка типа · имя (кнопка) · мета (`small.file-row-status`) · меню действий.

Мета: для файла — тип/размер как можно честно из манифеста/узла (сейчас
статус repair/orphan/shared). Длительность в мета **не выдумывать**.
Для папки — «N объектов», если это уже считается; иначе имя достаточно.

Иконка файла — **по классу**, не одна `file-text`:

| Что | Модификатор | Иконка Phosphor |
|---|---|---|
| папка | — | `folder` (есть) |
| `audio/*` | `.file-row-icon--audio` | `file-audio` |
| `video/*` | `.file-row-icon--video` | `file-video` |
| `image/*` без миниатюры | `.file-row-icon--image` | `file-image` |
| `application/pdf` | `.file-row-icon--doc` | `file-pdf` |
| xls / xlsx (`spreadsheetml.sheet`, `vnd.ms-excel`) | `.file-row-icon--doc` | `file-xls` |
| doc / docx (`wordprocessingml.document`, `msword`) | `.file-row-icon--doc` | `file-doc` |
| прочий `other` | `.file-row-icon--doc` | `file-text` |

Чистая функция `iconForFile(mime)` в том же месте, что фильтр (или
рядом в `files.jsx`/маленьком модуле) — чтобы тест мог проверить таблицу
без DOM. pptx и прочий office, которого нет в таблице → `file-text`,
не «похожий» ppt.

Картинка **с** готовой миниатюрой — `<img class="file-row-thumb">` /
кадр плитки, не иконка.

Цвета модификаторов — дословно из макета:

```css
.file-row-icon--audio { color: var(--accent); }
.file-row-icon--video { color: var(--accent-2); }
.file-row-icon--image { color: var(--accent-2); }
.file-row-icon--doc   { color: var(--muted); }
```

### 5.2. Плитки (`.file-grid` / `.file-tile`)

CSS — дословно из `files-B.html` (блок «СЛОВАРЬ экрана Хранилище»,
строки ~8084–8140). Раскладка плитки: `display:flex` колонка внутри
кнопки — это вид, не композиция экрана; так в макете, переносить как есть.

Содержимое плитки:

- кадр 1:1: миниатюра / иконка типа;
- бейдж длительности — **только если длительность реально откуда-то
  есть**. Сейчас источника нет → бейдж не рисовать (не «00:00»).
- имя, мета (размер или тип).

Клик по плитке = тот же обработчик, что у строки (`openEntry` / папка /
модалка документа).

«⋯» на плитке **обязательны** — то же `ActionsMenu`, что у строки
(переименовать / удалить / поделиться / …). Положение: `icon-btn` в
углу кадра (`inset-inline-end` + `inset-block-start` на
`.file-tile__frame`), чтобы не сжимать имя. Клик по ⋯ не открывает
файл (`stopPropagation`).

### 5.3. Виртуализация

Список: оставить `useVirtualWindow` (высота 56px).
Плитки: **без** той же виртуализации в этом этапе (высота не
фиксированная однозначно, `auto-fill`). Папка на 10⁴ фото — известный
лимит, не чинить здесь. Не ломать список, выключая хук «заодно».

## 6. CSS

В `custom.css` — новый блок «Хранилище, вариант Б», **после** существующих
`.file-row-*`. Перенести из макета:

- `.file-grid`, `.file-tile`, `.file-tile__frame`, `.file-tile__badge`,
  `.file-tile__name`, `.file-tile__meta`
- `.view-toggle .slice`
- `.mode-bar`, `.mode-bar__title`, `.mode-bar__n`
- `.file-row-icon--audio/video/image/doc`

Не копировать `.mock-bar` / `.mock-aside` / `.mock-note`.

Существующие `.file-row`, `.file-search-field`, `.file-breadcrumbs` не
ломать. У крошек после удаления `grow` корзина больше не должна
прижиматься вправо — самого элемента корзины там не будет.

Композиция экрана — только `.stack/.row/.bar/.reel/.grow/.rigid/.box`.
Никаких `margin` на новых классах, никаких физических `left/width`.
Исключение: `position: relative/absolute` у бейджа на кадре плитки —
как в макете (`inset-block-end` / `inset-inline-end`, логические).

## 11. Тесты до кода

Чистые функции, без DOM. Писать **до** правки `files.jsx`.

`tests/files-filter.test.js` (дополнить):

1. `filterByClass(entries, "all")` → все, включая папки.
2. `filterByClass(entries, "audio")` → только `audio/*`, папки выкинуты.
3. `mime == null` не попадает ни в один тип ≠ `all`.
4. Поиск ∩ тип: «а.mp3» + image → пусто; + audio → файл.
5. Пустая пачка типа → `[]`, не throw.

`recommendedLayout` / `layoutFor(type, override)`:

6. Без override: image/video → `grid`, all/audio/other → `list`.
7. С override: он побеждает рекомендацию.
8. После «сброса к all» layout = `list` независимо от override картинок.

`iconForFile(mime)`:

9. pdf / xlsx / docx → соответствующие имена; `audio/mpeg` → file-audio;
   `image/jpeg` → file-image; `application/zip` и `text/plain` → file-text;
   `null` → file-text (не throw).

Плейлист (маленькая `buildVisibleMediaPlaylist(entries, clickedId)`):

10. Только image/video/audio, порядок как во входе, папки и pdf выкинуты.
11. `position` кликнутого; если клик «подряд» — 0.
12. Клик по pdf в эту функцию не идёт (документы не в плейлисте).

Регрессия: существующие `files-*.test.js` и `media-buttons` (если есть)
зелёные. Тест, что `MediaButtons` по-прежнему вызывает `onOpen` при
клике — обязателен, если его ещё нет: повесить в
`tests/media-*.test.js` или короткий новый файл, чтобы чат не отъехал
молча.
