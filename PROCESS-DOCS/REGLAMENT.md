# LAYOUT.md — композиционные классы

Регламент раскладки для Уголка. Обязателен к соблюдению при генерации любой
разметки. Разделы 1–2 — минимум, который нужно держать в голове всегда.
Разделы 3–7 — на случай нестандартной задачи и при ревью.

Область действия — только уровень **композиции** (раздел 1). Регламент не
описывает `.btn`, `.card`, цвета, радиусы, тени и прочее оформление — это
отдельный, проектный слой, здесь не нормируется. «Обязателен для любой
разметки» значит: если на элементе решается вопрос раскладки — решение
берётся отсюда; вопрос вида — из оформительских классов проекта.

---

## 1. Три уровня. Смешивать запрещено

Каждый класс принадлежит ровно одному уровню. Класс, совмещающий два уровня, —
ошибка проектирования, а не удобство.

| Уровень | Что описывает | Меняется |
|---|---|---|
| **Композиция** | как элементы делят место | никогда (только при находке новой раскладки) |
| **Токены** | имена ролей: `--bg-raised`, `--space-m`, `--accent` | значения — от проекта; имена — нет |
| **Оформление** | цвет, радиус, шрифт, тень, состояния | свободно, под каждый проект |

Композиционный класс **не содержит ни одного цвета, шрифта, радиуса, тени**.
Оформительский класс **не содержит ни одного правила раскладки**.

Кнопка, карточка, модалка — это **сочетание** классов двух уровней на одном
элементе, а не отдельная сущность:

```html
<button class="bar btn">…</button>
```

`.bar` даёт раскладку внутри, `.btn` даёт вид. Ни один не знает о другом.

## 2. Классы

### Глобальные — объявляются один раз, на оболочку

| Класс | Правило |
|---|---|
| `.screen` | минимум одна видимая область (`dvh`) + безопасные зоны, документ вправе расти и скроллиться дальше. Для одиночных страниц (лендинг, экран входа) |
| `.shell` | ЖЁСТКО одна видимая область, сам никогда не скроллится — вся прокрутка обязана уйти во вложенный `.scroller`. Для SPA-каркаса приложения |
| `.scroller` | назначает хозяина прокрутки. **Ровно один на каждом пути от `.screen`/`.shell` до листа** |
| `.stick` | едет с потоком до края скроллера, дальше стоит |
| `.anchored` | прокрутка держится низа при добавлении содержимого (переписка) |

`.screen` и `.shell` — не варианты одного класса, а разные обязательства.
Перепутать — значит либо дать странице скроллиться там, где по архитектуре
обязан быть один-единственный внутренний скроллер, либо наоборот — запереть
контент, которому расти можно и нужно (см. раздел 4).

### Контейнеры — как дети делят место

| Класс | Правило |
|---|---|
| `.stack` | в столбик, между всеми один зазор |
| `.row` | в ряд, при нехватке переносятся **по одному** |
| `.bar` | в ряд, **без переноса**, при нехватке сжимаются |
| `.reel` | в ряд, без переноса, при нехватке **прокрутка** |
| `.switch` | в ряд, при нехватке **разом** в столбик, все сразу. Порог по умолчанию `30rem` (`--threshold`) |
| `.grid` | колонок столько, сколько влезет при минимальной ширине (по умолчанию `16rem`, `--min`) |
| `.columns` | колонки при заданной высоте, перенос вниз-вправо (газетная). **`--h` обязателен** — без него класс не работает (не «сжимается», а перестаёт переносить вовсе) |
| `.canvas` | прокрутка сразу по двум осям (таблица, карта) |
| `.layer` | дети в одной ячейке, друг на друге; высота по содержимому |

**Как выбрать среди «в ряд»**, если несколько кандидатов подходят:

- элементов немного, порядок неважен, перенос по одному — ничего страшного → `.row`
- ряд обязан остаться рядом, нехватка места — сжатие, не перенос (тулбар,
  шапка) → `.bar`
- элементов может быть много и они не должны сжиматься — вместо переноса
  прокрутка (лента стикеров, чипы фильтров) → `.reel`
- 2–3 крупных смысловых блока, при нехватке — **все разом** становятся
  колонкой, не по одному (сайдбар+контент, панель настроек) → `.switch`
- нужна сетка карточек без фиксированного числа колонок → `.grid`

### Дети — право на исключение

Родитель задаёт правило для всех. Ребёнок задаёт **отклонение для себя**.
Обратное запрещено: ребёнок не устанавливает общее правило.

| Класс | Правило |
|---|---|
| `.grow` | ем остаток (по оси родителя) |
| `.rigid` | держу свой размер, не сжимаюсь и не расту |
| `.self-start` / `.self-center` / `.self-end` | поперёк оси я иначе, чем остальные |
| `.over` | я поверх соседей по слою (внутри `.layer`) |

### Мера себя — композиции нет

| Класс | Правило |
|---|---|
| `.box` | падинг, рамка, фон. Единственный владелец «внутри» |
| `.center` | ограничить ширину и центрировать. Мера — длина строки |
| `.ratio` | держать пропорцию независимо от содержимого |
| `.truncate` | не влезло — обрезать (одна строка или N) |

### Параметры — через переменные, не через классы

Зазор, минимальная ширина колонки, порог перелома, мера строки — переменные
на элементе. Значения берутся **только из токенов**, не из чисел.

```html
<div class="stack" style="--gap: var(--space-l)">
<div class="grid" style="--min: 14rem; --gap: var(--space-m)">
<div class="center" style="--measure: 46rem">
```

Классы `.stack-sm` / `.stack-md` / `.stack-lg` **запрещены** — это
комбинаторный взрыв, ради ухода от которого всё и делалось.

## 3. Пять запретов

Все пять грепаются. Нарушение = выход за модель, а не стилистический спор.

1. **Нет `margin` на компонентах.** Зазор принадлежит контейнеру (`--gap`).
   Компонент не задаёт своё положение снаружи. Исключение — `margin-inline:
   auto` в `.center` (раздел 5): это самоцентрирование бокса внутри
   собственного родителя, симметрично с обеих сторон, а не отступ,
   которым компонент отталкивается от соседей. Не нарушение, но легитимный
   ложный срабатыватель грепа — держать в уме при ревью.
2. **Нет медиазапросов в компонентах.** `.switch`, `.grid`, `.columns` реагируют
   на ширину **контейнера**, а не экрана. `@media` допустим только на уровне
   оболочки и для `prefers-*`.
3. **Нет `position: absolute` ради наложения.** Наложение — это `.layer`.
   `absolute` только когда действительно нужно выпасть из потока.
4. **Нет структурных селекторов.** `.card > div > span` запрещён. Разрешены
   селекторы состояния (`:hover`, `:focus-visible`, `[aria-expanded]`).
5. **Нет чисел вне токенов.** `gap: 12px` — ошибка. `gap: var(--space-s)` — норма.
   Исключения: `1px` для линий, `50%` для круга, `1` для `flex`, а также
   фолбэк-значения внутри `var(--x, значение)` в РЕАЛИЗАЦИИ самих
   композиционных классов (раздел 5) — `16rem` в `.grid`, `30rem` в
   `.switch`, `65ch` в `.center` и т.п. Это не числа в разметке, а сама
   шкала по умолчанию; грепается всё остальное — сама реализация раздела 5
   из проверки исключена.

Плюс два, не грепающихся, но обязательных:

6. **Логические свойства.** `padding-inline-start`, а не `padding-left`.
   `margin-inline`, `border-inline-start`, `inline-size`, `block-size`.
   Из 12 поддерживаемых языков проекта (ru/en/es/de/ja/fr/pt/it/nl/pl/tr/zh)
   RTL нет ни одного — это не подготовка к конкретному языку, а нулевая
   цена по умолчанию: пишется не сложнее физических свойств, ничего не
   ломает при LTR-only и снимает вопрос, если языковой список когда-нибудь
   расширится.
7. **Анимировать только `transform` и `opacity`.** `left`, `width`, `margin`
   пересчитывают раскладку на каждом кадре и ломают композицию соседей.

## 4. Эталоны

### Оболочка приложения (SPA-каркас, сам не скроллится)

```html
<div class="shell stack">
  <header>…</header>
  <div class="switch grow">
    <aside class="rigid scroller">…</aside>
    <main class="grow scroller">…</main>
  </div>
  <footer>…</footer>
</div>
```

Шапка сверху и подвал снизу — **следствие** того, что средний блок ест остаток.
Их никто не позиционировал. `.shell` не скроллится сам никогда — прокрутка
уходит в `.scroller` внутри. Сайдбар и контент — сёстры, не предок/потомок,
поэтому у каждой свой `.scroller` без нарушения правила «один на ветку»:
правило считается по пути от `.shell` до листа, а путей тут два, не один.

### Одиночная страница (лендинг/вход — документ вправе скроллиться)

```html
<body class="screen stack">
  <header>…</header>
  <main class="grow">…</main>
  <footer>…</footer>
</body>
```

Ни `.shell`, ни `.scroller` — страница просто высотой минимум в экран,
дальше растёт вместе с контентом, скроллит сам документ. Не окружать
`.scroller`-ом то, что и так прекрасно скроллится браузером по умолчанию.

### Комментарий (двухколоночный, дата прижата к низу)

```html
<article class="comment bar" style="--gap: var(--space-m)">
  <img class="avatar rigid">
  <div class="stack grow" style="--gap: var(--space-2xs)">
    <header class="row" style="--gap: var(--space-xs)">имя · ник</header>
    <p class="body grow">текст</p>
    <footer class="bar" style="--gap: var(--space-s)">дата · ответить</footer>
  </div>
</article>
```

`.bar` снаружи — аватар и текст не переносятся. `.row` в шапке — длинный ник
уезжает вниз, а не выдавливает соседей. `.grow` на колонке ест ширину,
`.grow` на тексте ест высоту и **этим** прижимает дату вниз. Без `margin-top:
auto`, без `absolute`.

Дерево ответов — рекурсия, не новый примитив:

```html
<div class="replies stack">…комментарии…</div>
```

`.replies` — оформительский класс: логический отступ и направляющая линия.
Раскладка — обычный `.stack`.

### Кнопка со сложным содержимым

```html
<button class="bar btn" style="--gap: var(--space-xs)">
  <i class="icon rigid"></i>
  <span class="grow truncate">Длинный текст действия</span>
  <i class="chevron rigid"></i>
</button>
```

Внутри кнопки работают те же правила, что внутри страницы. Композиция
рекурсивна и не зависит от размера элемента.

## 5. Реализация

```css
.stack  { display: flex; flex-direction: column; gap: var(--gap, 0); }
.row    { display: flex; flex-wrap: wrap;   gap: var(--gap, 0); }
.bar    { display: flex; flex-wrap: nowrap; gap: var(--gap, 0); }
.reel   { display: flex; flex-wrap: nowrap; gap: var(--gap, 0);
          overflow-x: auto; } /* см. примечание про overflow-x/-y ниже */
.switch { display: flex; flex-wrap: wrap;   gap: var(--gap, 0); }
/* Формула Хейдона Пикерина ("The Switcher"): при ширине контейнера МЕНЬШЕ
   --threshold выражение в скобках положительно и умножается на 999 — basis
   выстреливает в тысячи %, элемент не помещается в строку и переносится;
   при ширине БОЛЬШЕ --threshold выражение отрицательно — basis уходит в
   глубокий минус, браузер клампит его до 0, элемент остаётся в ряду. Порог
   один on/off, не плавное сжатие — оба соседа складываются в столбик разом. */
.switch > * { flex-basis: calc((var(--threshold, 30rem) - 100%) * 999);
              flex-grow: 1; }
.grid   { display: grid; gap: var(--gap, 0);
          grid-template-columns: repeat(auto-fit,
            minmax(min(var(--min, 16rem), 100%), 1fr)); }
/* --h без фолбэка НАРОЧНО (единственный такой параметр во всём разделе):
   без явной высоты колонкам некуда переносить — --h обязан прийти снаружи. */
.columns{ display: flex; flex-direction: column; flex-wrap: wrap;
          block-size: var(--h); gap: var(--gap, 0); }
.canvas { overflow: auto; }
.layer  { display: grid; }
.layer > * { grid-area: 1 / 1; }

.grow   { flex: 1 1 auto; min-inline-size: 0; min-block-size: 0; }
.rigid  { flex: 0 0 auto; }
.self-start  { align-self: start; }
.self-center { align-self: center; }
.self-end    { align-self: end; }
.over        { z-index: 1; }

.screen   { min-block-size: 100dvh;
            padding-block-end: env(safe-area-inset-bottom); }
.shell    { block-size: 100dvh; overflow: hidden;
            padding-block-end: env(safe-area-inset-bottom); }
.scroller { overflow-y: auto; overscroll-behavior: contain; } /* см. примечание ниже */
.stick    { position: sticky; inset-block-start: 0; }
.anchored { overflow-anchor: auto; }

.box      { padding: var(--pad, 0); }
.center   { max-inline-size: var(--measure, 65ch); margin-inline: auto; }
.ratio    { aspect-ratio: var(--aspect, 16/9); } /* НЕ --ratio — см. примечание ниже */
.truncate { overflow: hidden; text-overflow: ellipsis;
            display: -webkit-box; -webkit-box-orient: vertical;
            -webkit-line-clamp: var(--lines, 1); }
```

`min-inline-size: 0` на `.grow` обязателен: без него флекс-ребёнок не сжимается
меньше содержимого, и длинное слово ломает раскладку. Самая частая причина
горизонтальной прокрутки.

**`.scroller`/`.reel` — намеренное исключение из правила 6 (логические
свойства).** `overflow-inline`/`overflow-block` как отдельные CSS-свойства
браузерами не реализованы (были в черновике спецификации, из живых движков
выпилены) — правило-в-лоб «просто добавь `-inline`/`-block`» здесь сломало
бы прокрутку молча, без ошибки в консоли. Взяты проверенные `overflow-x`
(`.reel`) и `overflow-y` (`.scroller`) — единственное место в разделе 5, где
физические свойства предпочтены логическим осознанно. Проект без RTL-языков
(правило 6 выше), поэтому цена исключения — ноль; если у `overflow`
когда-нибудь появится надёжно поддержанная логическая форма — заменить одним
местом здесь.

**`.ratio` использует `--aspect`, не `--ratio` — это проектная поправка, не
универсальная.** В Уголке `--ratio` уже занят глобально (модульная шкала
шрифта, `tokens`: `--ratio: 1.2`/`1.25`, кастомное свойство наследуется).
Назови `.ratio` в REGLAMENT'е как задумано (`--ratio`) — и любой голый
`<div class="ratio">` без явного `style="--ratio:…"` тихо унаследует шкалу
шрифта вместо фолбэка `16/9`: переменная не «не задана», она задана на
`:root`, фолбэк в `var()` не сработает никогда. Перед переносом регламента
в новый проект — свериться с его собственным списком токенов на этот же
класс коллизий, не только на этот конкретный случай.

## 6. Чего модель не покрывает

Здесь она честно расписывается в бессилии. Не изобретать композиционные классы
для этих случаев — это другой уровень.

- **Прижатие к низу требует источника лишней высоты.** `.grow` даёт механизм,
  но откуда взяться остатку — решает оформление (`min-block-size`, размер
  аватара). Без источника прижимать не к чему.
- **Порог `.switch` — ширина контейнера, а не «мобильник/десктоп».** Если нужно
  «сайдбар превращается в выдвижную панель» — это состояние компонента, не
  раскладка.
- **Ритм, иерархия, размер шрифта, «почему заголовок такой»** — вне модели.
- **Что именно складываем** — тоже вне. Модель отвечает только на «как уживаются».
- **`@container`-запросы — не конкурент этой модели, а другой инструмент.**
  `.switch`/`.grid` отвечают на вопрос «как делятся местом» без единой
  строчки медиа- или контейнер-запроса — это и есть их смысл. `@container`
  отвечает на другой вопрос — «в каком визуальном режиме находится
  компонент при такой-то ширине» (свернуть подпись, скрыть колонку,
  сменить масштаб иконки) — то, что решение о раскладке само по себе не
  покрывает. В проекте уже есть работающий пример (`.content-wrapper`,
  `container-type: inline-size` объявлен один раз, экраны ниже используют
  `@container` без повторного объявления) — тот случай, где нужен именно
  этот инструмент, не замена композиционных классов.
- **«Ровно один `.scroller`» считается на ветке — пути от корня (`.screen`/
  `.shell`) до листа, а не на странице целиком.** Сайдбар и основной контент
  под одним `.shell` — сёстры, не предок/потомок, у каждой законно свой
  `.scroller` одновременно (см. пример в разделе 4).

## 7. Чеклист ревью

Перед принятием любой сгенерированной разметки:

- [ ] Ни одного `margin` на компоненте — зазоры через `--gap`
- [ ] Ни одного `@media` вне оболочки
- [ ] Ни одного `position: absolute` там, где хватило бы `.layer`
- [ ] Ни одного числа вне токенов
- [ ] Ни одного `left` / `right` / `width` / `height` — только логические
      (кроме `overflow-x`/`overflow-y` в `.reel`/`.scroller` — раздел 5)
- [ ] Ровно один `.scroller` на каждом пути от `.screen`/`.shell` до листа
- [ ] На каждом `.grow` вдоль главной оси есть `min-inline-size: 0`
- [ ] Компонент не знает, где стоит: убери его из родителя — он не сломается
- [ ] Каждый класс на элементе принадлежит одному уровню
- [ ] Оболочка выбрана осознанно: одиночная страница, которая вправе
      скроллиться сама, — `.screen`; SPA-каркас, где скроллить может только
      вложенный `.scroller`, — `.shell`

Последний пункт — главный. Если класс одновременно раскладывает и красит,
он не переживёт переноса в следующий проект.
