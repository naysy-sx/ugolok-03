# MOLECULES.md — словарь молекул оформительского слоя

Каталог классов **оформительского слоя** (REGLAMENT.md §1: композиция/
токены/оформление — это третий уровень), заведённых циклом JOURNAL-REDESIGN
+ ACCOUNT-REDESIGN. Не путать с REGLAMENT.md — тот про композицию
(`.stack/.row/.bar/...`), она универсальна и переносима между проектами;
здесь — проектный словарь вида, специфичный для Уголка.

**Правило:** прежде чем писать в новом ТЗ разметку под очередную "панель",
"строку настройки", "врезку-предупреждение" и т.п. — сверься с этим
списком. Новую молекулу заводим, только если ни одна из существующих не
подходит НИ С МОДИФИКАТОРОМ. Опиши здесь любую новую, до того как ТЗ уйдёт
исполнителю — иначе список гниёт быстрее, чем помогает.

Работает и для написания ТЗ (проверить перед тем, как выдумывать новый
класс), и для реализации (проверить, что не завёл дубликат).

## Панели и строки

### `.panel` (+ `.panel__title`, `.panel__hint`, `.panel--danger`)

Карточка-раздел: фон `--surface`, рамка, `--radius-lg`, паддинг
`--space-m`. `.panel__title` — заголовок в `--font-display`/`--step-1`,
иконка внутри (`.panel__title > .icon`) приглушена и не растёт (`flex:
none`). `.panel--danger` красит рамку/фон/заголовок в тон `--bad` (было
в `profile.jsx`, "Опасная зона").

Отдельное правило `.panel :is(input, select, textarea):not([type=
checkbox], [type=radio], [type=range], [type=color])` поднимает
вложенные поля на тон выше фона панели — оба были `--surface`, контрол
растворялся в подложке.

Используется: `profile.jsx`, `security.jsx`, `settings.jsx`.

### `.set-row` (+ `__text`, `__hint`, `__control`, `__switch`) + `.set-list`

Молекула "подпись слева — контрол справа", была написана руками 46 раз
через инлайновый `justify-content: space-between`. `.set-row__text` —
`flex-basis: 16rem`, при нехватке ширины контрол сам переносится под
подпись (без media/container-запроса). `.set-row__control` точечно
возвращает `select` из full-width (в `minimal.css`/elements у `select`
стоит `width: 100%` — верно для форм, но в строке настройки давало селект
во всю ширину экрана ради выбора из четырёх слов; то правило НЕ трогать,
переопределяется здесь).

`.set-list > * + *` рисует разделитель (`border-block-start` +
`padding-block-start`) между строками-детьми — родитель отвечает за
разделение, не каждая строка сама.

Используется: `profile.jsx`, `settings.jsx`.

> ⚠️ **Ловушка, уже найдена живьём** (см. «Грабли» ниже, п.1): ребёнок
> `.set-list`, обнуляющий свою рамку инлайновым `border: "none"`, глушит
> унаследованный разделитель родителя — тот тоже рисуется через
> `border-block-start`, а инлайн бьёт border на ЛЮБОЙ стороне.

### `.exceptions` (+ `.exceptions__body`)

Свёрнутый по умолчанию `<details>` для длинных списков-исключений
(вместо таблицы, которая висела на экране развёрнутой всегда). Рамка +
радиус + `--surface-raised`, `summary` без родного маркера, шеврон
разворачивается (`rotate`). Паддинг задаёт `.exceptions__body`, не первый
элемент внутри (раньше был инлайновый `padding-block-start`, содержимое
слева/справа упиралось в границу).

Используется: `settings.jsx` (исключения по контактам/каналам).

## Кнопки и переключатели

### `.seg` + `.slice` / `.slice--on`

Сегмент из 2–3 взаимоисключающих кнопок (например тема: система/светлая/
тёмная). `.seg .slice` — скруглены только крайние кнопки, соседние
состыкованы `margin-inline-start: calc(var(--border-width) * -1)`.
Активная (`.slice--on`) поднята `z-index: 1` — иначе теряет рамку с одной
стороны там, где сосед перекрывает её границу отрицательным отступом.

`.slice--on` — общий модификатор состояния "выбран", используется не
только внутри `.seg`: чипы `.filter-reel` "Журнала" тоже красятся им, но
СО СВОИМ переопределением цвета (`border-color: currentColor` вместо
общего акцента — иначе выбор "Модерации" красился бы в тот же тон, что
"Сообщения").

Используется: `settings.jsx` (`.seg`, тема), `journal.jsx` (`.slice--on`
без `.seg`, чипы фильтра).

### `.callout` (+ `--warn`, `--bad`)

Врезка-предупреждение: паддинг + радиус + рамка + `--surface-raised`.
Модификаторы красят только `border-color` (`--warn`) или `border-color`
+ `color` (`--bad`) — не всю заливку, тон должен читаться, а не кричать.

Используется: `profile.jsx`, `security.jsx`, `settings.jsx`.

### `.swatch`

Образец цвета САМ является кнопкой (было 15 отдельных заливных
`<button>` акцентным цветом с кружком нужного оттенка внутри — цвет,
который выбираешь, спорил с цветом кнопки, на которой он нарисован).
Круглая, `2.25rem`, рамка прозрачная кроме `[aria-pressed="true"]`.

Используется: `settings.jsx` (пресеты акцентного цвета).

### `.badge` (+ `--warn`)

Метка-пилюля: рамка + `--radius-full` + мелкий текст. Модификатор
`--warn` красит рамку/фон/текст в тон `--warn` (тот же приём, что
`.callout--warn`/`.badge--warn`, не путать с `.badge-on` — другое
назначение, статус сервера в `settings.jsx`). Нейтральный `.badge` без
модификатора заведён сразу как базовый уровень молекулы, хотя сегодня
нигде не применяется без `--warn`.

Используется: `discovery.jsx` (метка "только вы" на канале без читателей).

### `.ring` (+ `.track`, `.live`, `.is-low`)

Кольцо остатка (замена текстового таймера) — SVG `<circle>` с
`stroke-dasharray`/`stroke-dashoffset`, параметризовано инлайн `--circ`
(2πr, геометрическая константа контура канвы, НЕ токен) и `--p` (доля
оставшегося времени, 0..1) — тот же приём параметризации через
переменные на элементе, что `--gap`/`--min` у композиционных классов
(REGLAMENT.md §2). `.track` — фон-дорожка (`--border`), `.live` —
собственно кольцо (`--good`, при `.is-low` — `--warn`), `transform:
rotate(-90deg)` начинает отсчёт с 12 часов.

Используется: `discovery.jsx` (остаток трансляции "Знакомств").

## Фильтр по категории (два вида одного контрола)

### `.filter-slot` / `.filter-reel`

Оба вида фильтра существуют в DOM ОДНОВРЕМЕННО, показывается всегда
ровно один — переключение чистым `@container`, без JS:

```css
@container (max-width: 93.75em) { .filter-reel { display: none; } }
@container (min-width: 93.75em) { .filter-slot { display: none; } }
```

Порог был `52em`, поднят до `93.75em` (= 1500px при 16px корне) — живой
фидбег: семь категорий не помещались в ряд вплоть до этой ширины и
уезжали в `.reel`-скролл без видимого скроллбара, читалось как обрезка.
Отступ у `.filter-slot` (`padding-block-end`) даёт слот-обёртка, а не сам
компонент (REGLAMENT.md §3 п.1 — margin/паддинг-позиционирование не на
компоненте).

Используется только: `journal.jsx`. Общий приём (два вида контрола +
`@container`-переключение) годится для любого будущего экрана с тем же
классом задачи — не изобретать заново.

### `.jcat--{lamp,draught,bad,muted}`

Тон категории, ДВА разных правила для двух контекстов: в пункте МЕНЮ
красится только иконка (`.jcat--lamp > .icon`, `> summary > .icon:first-
child`), в чипе `.filter-reel` красится весь текст (`.slice.jcat--lamp
{ color }`, `.jcat .icon { color: inherit }`) — в плотном списке меню
цветной текст читается хуже и спорит с `--fg`, в чипе наоборот акцент
уместен. Переиспользует те же 3 тона, что `.jtype--lamp/--draught/--bad`
(лента "Журнала") — не выдумывать четвёртый набор оттенков под то же
смысловое деление.

Используется: `journal.jsx`.

## Специфичные для одного экрана (не молекулы общего назначения)

Ниже — тоже оформительский слой, но привязан к конкретной разметке
одного экрана. Не пытаться "обобщить" без реальной второй потребности.

- **`.ident`/`.ident__photo`/`.ident__body`** + **`.ava`/`.ava__actions`/
  `.ava__btn`** (`profile.jsx`) — шапка профиля, двухколоночная (фото/
  тело); `.ava` — контейнер-`.layer` для наложения, `.ava__actions` —
  полупрозрачная накладка снизу (`backdrop-filter: blur`) с двумя
  одинаковыми кнопками `.ava__btn` (раньше "Заменить" и "Из хранилища"
  были парой в разных формах — пилюля-`label` и обычная кнопка).
- **`.keybox`** (`profile.jsx`) — плашка npub + кнопка-копия, `border:
  none` (рамка убрана намеренно: на панели того же тона от рамки+
  заливки `--surface` оставалась одна рамка, поле переставало читаться
  как поле — различие несёт только тон `--surface-raised`).
- **`.jfeed`/`.jitem`/`.jtype`/`.jgroup__date`** (`journal.jsx`) — лента:
  `.jfeed` — CSS grid с `subgrid`, колонка иконок/времени выровнена по
  всей ленте дня, не только в своей строке; `.jgroup__date` — липкий
  заголовок дня (`.stick`, композиционный), **обязан** быть непрозрачным
  (`background-color: var(--bg)`) — без этого строки просвечивают сквозь
  заголовок при прокрутке; `.jitem`/`.jread` — точечная кнопка
  "прочитано" поверх строки, `position: absolute`, видна по hover/focus.

  > ⚠️ Незакрытая находка (см. CONTRACTS.md, JOURNAL-REDESIGN): `.jread`
  > получает фон только на СВОЁМ `:hover`/`:focus-visible`, а видимость
  > (`opacity: 1`) — уже от `.jitem:hover` (вся строка). В промежутке
  > между этими двумя моментами иконка рисуется на прозрачном фоне
  > поверх `.jtime`/`.jdot`. Решение отложено пользователем — фикс:
  > дать `.jread` тот же непрозрачный фон, что у `.jgroup__date`.

## Уже наступали на эти грабли

1. **Инлайн `border`/`padding` на ребёнке `.set-list` глушит родительский
   разделитель.** `.set-list > * + *` рисует `border-block-start` +
   `padding-block-start` на своих детях. Если ребёнок (например
   `fieldset`, чтобы снять свою нативную рамку) ставит блочный `border:
   "none"`/`padding: 0`, это гасит разделитель родителя целиком — инлайн
   бьёт border/padding на любой стороне, даже если нужна была только
   одна. Чинить точечно логическими сторонами (`borderInlineStart/End`,
   `borderBlockEnd`, `paddingInline`, `paddingBlockEnd`), никогда
   блочным сбросом всех четырёх сторон разом.
2. **`fieldset`/аналогичный элемент без внешней рамки-опоры выглядит
   "голым" при обнулении border/padding.** Если родителя-`.panel`/`.box`
   нет, обнулять нечего — `minimal.css` уже даёт `fieldset` token-based
   рамку+радиус+паддинг бесплатно (тот же вид, что у `unlock.jsx`/
   `permission-editor.jsx`), инлайновый сброс там не нужен вовсе.
3. **`button:has(> .icon)`/`[type="button"]:has(> .icon)`** — глобальная
   ловушка `padding-inline`, всплывала уже трижды-четырежды на разных
   icon-only кнопках (`.icon-btn`, `.account-key`, `.fav-toggle`, `.act`,
   `.quick` — см. `custom.css` рядом с этими классами). При заведении
   новой icon-only кнопки — проверять эту специфичность сразу explicitly
   (`.new-btn:has(> .icon) { padding-inline: ... }`), не постфактум по
   живому фидбеку.
4. **«Одна линия под шапкой экрана» — готовый паттерн, не изобретать
   заново.** `.section-header:has(+ .slices-zone) { border-block-end:
   none; }` + `.slices-zone:has(.tabs) { ... }` уже решают "две-три линии
   подряд зажимают ряд вкладок/срезов в тиски" для ЛЮБОГО экрана со
   срезами. Затронуты `chat`/`files`/`channel`/`channel-chat`/`journal`/
   `settings` — при следующей правке `.section-header`/`.slices-zone`
   держать в уме все шесть.
5. **Пороги `@container` подбираются по РЕАЛЬНОЙ ширине контента, не на
   глаз.** `.filter-reel`/`.filter-slot` пришлось поднимать постфактум
   (52em → 93.75em) — уже готовое число компонентов/чипов проверить
   живьём на реальной ширине контейнера ДО того, как порог уйдёт в ТЗ,
   а не после жалобы, что обрезается.
