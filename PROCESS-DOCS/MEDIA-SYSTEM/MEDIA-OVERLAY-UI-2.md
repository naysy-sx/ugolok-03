## 0. Инварианты

Действуют И-A … И-F из `MEDIA-OVERLAY-UI.md` без изменений. Добавляются:

**И-G. Единственный писатель.** Классы `is-dragging` / `is-settling` и
переменные `--drag-px` / `--media-pull` пишутся ровно из одной функции —
функции выхода автомата жеста. Сейчас писателей пять (`pointerdown`,
`settleTrack`, `finish`, `rAF` внутри `finish`, `endGesture`), и порядок
между ними зависит от кадровой развёртки браузера. Это источник всех
наблюдаемых «иногда».

**И-H. Доводка идентифицируется поколением.** У каждой доводки свой
целочисленный номер. Событие завершения с чужим номером игнорируется.
Флаг `done` этого не даёт: фолбэк по таймеру от прошлой доводки прилетает
в новую.

**И-I. Анимации сворачивания нет в автомате сессии.** `display`
переключается мгновенно, каскад рисует вид по двум измеренным
прямоугольникам. Промежуточное состояние в δ сделало бы автомат
зависимым от завершения анимации, то есть от кадровой развёртки — ровно
то, от чего `media-machine.js` сейчас свободен и за что его можно гонять
в `node --test` без jsdom.

**И-J. `repeat` и `autoplay` — компоненты кортежа, не состояния.** Они
влияют ровно на две клетки δ (`ended` и `open`) и не порождают новых
состояний. Если правка требует завести `LOOPING` или подобное — правка
спроектирована неверно.

**И-K. Плашка не размонтируется.** При живой сессии `.media-mini-bar`
присутствует в DOM всегда; `full`/`mini` управляют видимостью, а не
монтированием. Иначе каскад нечего измерять, а И-A ломается на видео.

## Этап 7 — автомат жеста

### 7.0 Сначала два точечных исправления

Если ещё не применены — применить до всего остального, они независимы.

**Расстояние доводки берётся не от того элемента.** `g.widthPx` считается
по `viewportRef`, у которого есть горизонтальный паддинг `var(--space-l)`.
Ширина слайда равна ширине `.media-overlay-inner`, то есть на два паддинга
меньше (около 64 px на десктопе). Лента доезжает дальше, чем на слайд, и
при сбросе `--drag-px` дёргается назад.

```js
g.widthPx = innerRef.current?.getBoundingClientRect().width ?? 0;
```

**`requestAnimationFrame` внутри `finish()` отменяет `transition: none`.**
`finish` вызывается из `transitionend`, который доставляется на шаге
«update animations and send events»; колбэк `rAF`, поставленный оттуда,
выполняется на следующем шаге **того же кадра**, до пересчёта стиля. Стиль
считается один раз за кадр — и к этому моменту `is-dragging` уже снят,
`--drag-px` уже ноль, а зафиксированное ранее состояние было `−W` с живым
переходом. Браузер анимирует возврат. Это и есть «второй вылет».

```js
el.classList.add("is-dragging");
if (direction) (direction === "next" ? mediaNext : mediaPrev)();
el.style.setProperty("--drag-px", "0px");
void el.offsetWidth; // форс пересчёта, пока transition:none в силе
el.classList.remove("is-dragging");
```

`rAF` убрать целиком. Приём уже используется в `playSwapFade` — не новый
для проекта.

### 7.1 Новый модуль `src/domain/media/gesture-machine.js`

Чистый, без DOM, тестируется в `node --test` как `media-machine.js`.
Автомат Мура: δ + функция выхода λ.

```js
export const GESTURE_STATES = ["IDLE", "PRESSED", "DRAG_H", "DRAG_V", "SETTLING"];
export const GESTURE_EVENTS = ["down", "move", "up", "cancel", "settleEnd"];

export function gestureTransition(state, event, payload) { /* → next */ }
export function gestureOutput(state) { /* → { dragging, settling, dragPx, pull } */ }
```

Форма состояния: `{ name, axis, dx, dy, dir, gen }`, где `dir ∈ {null,
"next", "prev"}`, `gen` — номер поколения доводки (И-H).

### 7.2 Таблица переходов

| | `down` | `move` | `up` | `cancel` | `settleEnd(gen)` |
|---|---|---|---|---|---|
| **IDLE** | → PRESSED | — | — | — | игнор |
| **PRESSED** | игнор | ось не определилась → PRESSED; горизонт → DRAG_H; вертикаль → DRAG_V | → IDLE, **тап проходит** | → IDLE | игнор |
| **DRAG_H** | игнор | → DRAG_H | коммит → SETTLING(dir, gen+1); иначе → SETTLING(null, gen+1) | → SETTLING(null, gen+1) | игнор |
| **DRAG_V** | игнор | → DRAG_V | коммит → закрытие сессии, → IDLE; иначе → IDLE | → IDLE | игнор |
| **SETTLING** | **завершить доводку немедленно, → PRESSED** | игнор | игнор | завершить немедленно, → IDLE | `gen` совпал → IDLE; иначе игнор |

Три клетки — новые, и каждая соответствует наблюдавшемуся багу.

`down` в `SETTLING` — сейчас новый жест начинается, пока взведённый
`finish` жив, и тот доезжает посреди чужого жеста, дёргая `mediaNext` под
пальцем. Это и есть «иногда откатывается назад».

`settleEnd` с чужим `gen` — фолбэк `setTimeout(finish, 500)` от прошлой
доводки попадает в новую.

`up` в `PRESSED` — нажатие без определившейся оси обязано пройти к кнопке;
это единственный случай, когда `didDragRef` взводить нельзя.

### 7.3 Функция выхода

| состояние | `is-dragging` | `is-settling` | `--drag-px` | `--media-pull` |
|---|---|---|---|---|
| IDLE | нет | нет | 0, без перехода | 0, с переходом |
| PRESSED | да | нет | 0 | 0 |
| DRAG_H | да | нет | живое значение | 0 |
| DRAG_V | нет | нет | 0 | живое значение |
| SETTLING | нет | да | ±ширина слайда | 0 |

`media-overlay.jsx` только шлёт события и применяет результат λ к
`trackRef`. Ни одна из пяти прежних точек больше классов не пишет (И-G).

«Завершить доводку немедленно» обязана быть синхронной и идемпотентной:
применить позицию, снять классы, поднять `gen`. Без этого клетка
`down`/`SETTLING` не закрывается, а переезжает в другое место.

### 7.4 Тесты `tests/media-gesture-machine.test.js`

## Этап 8 — вёрстка мини-бара

Макет: `mini-bar-mockup.html`. Переносится в `custom.css` целиком, замена
блока `.media-mini-bar*` (строки 2316–2355 до правок этапа 1).

### 8.1 Разметка

Две строки вместо одной. Причина: в однострочной раскладке имени
доставалась треть ширины, а строка «0:00 / 2:34 · 3 из 5» меняла
ширину на каждой секунде и дёргала правый край.

```
div.media-mini-bar                       (data-cls, data-playing, role=status)
  div.media-mini-bar-progress            (полоса по верхней кромке, кликабельна)
  div.media-mini-bar-head
    div.media-mini-bar-name.media-mini-bar-grab
      span.media-mini-bar-name-inner
        span.media-mini-bar-name-stem    (имя без расширения, обрезается)
        span.media-mini-bar-name-ext     (расширение, НЕ сжимается)
    span.media-mini-bar-rank             ("3/5", tabular-nums)
  div.media-mini-bar-row
    div.media-mini-bar-preview.media-mini-bar-grab
      div.media-mini-bar-eq              (три полосы, только для audio/video)
    span.media-mini-bar-time             ("1:24 / 3:47", min-width 6.2ch)
    span.grow
    div.media-mini-bar-controls          (prev, play, next)
    div.media-mini-bar-aux               (repeat, restore, close)
```

Расширение отдельным узлом — чтобы при обрезке было видно
«дорога-домой-финальный-монт….mp4». У файлов из одной выгрузки
различается именно хвост имени, а расширение говорит, чего от файла ждать.

Разворот доступен тремя способами: кнопка `is-restore` (единственная
обведённая в плашке), тап по обложке, тап по имени. Кнопка 2rem пальцем
берётся плохо, полоса в половину плашки — хорошо.

### 8.2 Бегущая строка

Не бесконечная. Два прохода туда-обратно после смены файла, дальше
остановка; продолжение — только по `:hover` / `:focus-within`.

Обоснование, не вкусовое: плашка живёт на экране минутами, постоянное
движение в периферийном зрении утомляет; WCAG 2.2.2 требует способа
остановить автоматическое движение длительностью более пяти секунд.

Замер переполнения делается **с выключенной обрезкой** — при
`text-overflow: ellipsis` значение `scrollWidth` равно `clientWidth`, и
наивная проверка всегда говорит «влезло»:

```js
useLayoutEffect(() => {
	const box = nameRef.current;
	if (!box) return;
	box.classList.remove("is-marquee");
	box.style.setProperty("--marquee-shift", "0px");
	const id = requestAnimationFrame(() => {
		box.classList.add("is-marquee");
		const overflow = box.firstElementChild.scrollWidth - box.clientWidth;
		if (overflow <= 1) {
			box.classList.remove("is-marquee");
			return;
		}
		box.style.setProperty("--marquee-shift", `${overflow + 8}px`);
		box.style.setProperty("--marquee-dur", `${Math.min(12, Math.round(5 + overflow / 28))}s`);
	});
	return () => cancelAnimationFrame(id);
}, [mediaRef.name, session.display]);
```

Верхняя граница 12 с — при именах под сотню символов проход иначе
становится неприлично долгим. Пересчёт при изменении ширины — через
`ResizeObserver` на самой плашке, не через `window.resize`.

При `prefers-reduced-motion: reduce` прокрутки нет, остаётся обрезка —
правило уже в CSS макета.

### 8.3 CSS

Взять из макета блок между комментариями «МИНИ-БАР» и «Каскад» целиком.
Заменить литералы на токены там, где в макете их нет: тени — `--shadow`,
скругления — `--radius`/`--radius-md`, скорости — `--transition-speed`,
кривые — `--ease`/`--ease-io`. Литеральных цветов в блоке быть не должно;
единственное исключение — `oklch(0.12 0.02 var(--hue) / …)` в градиенте
поверх обложки, он умышленно не следует теме (лежит на кадре).

Эквалайзер рендерить только при `cls !== "image"` — для картинок плашки
не существует по И-E.

## Этап 9 — каскад сворачивания и разворачивания

### 9.1 Механика

FLIP по двум прямоугольникам: измерить `.media-overlay-viewport`,
измерить `.media-mini-bar`, пустить три рамки из первого во второй с
задержкой 55 мс между ними. Рамки живут в отдельном слое
`.media-fold-layer`, ничего не двигают, не участвуют в раскладке и не
ловят события.

По И-K плашка присутствует в DOM при живой сессии всегда, поэтому
измерение не требует трюка «показать на кадр» из макета — там он был
уместен, в Preact так делать нельзя: `hidden` управляется рендером, и
синхронное дёрганье атрибута разъедется с тем, что думает компонент.
Видимость переключается классом, `getBoundingClientRect()` работает и на
`opacity: 0` элементе, если он не `display: none`.

### 9.2 Асимметрия направлений

Разворот — не то же самое, что сворачивание в обратную сторону.

| | сворачивание | разворот |
|---|---|---|
| очерёдность рамок | 0, 1, 2 | 2, 1, 0 |
| длительность | 300 мс | 340 мс |
| кривая | `--ease-io` | `--ease` |
| скругление | 1.25rem → 0.875rem | 0.875rem → 1.25rem |

При сворачивании первой уходит внешняя рамка и затягивает остальные
внутрь; при развороте первой вылетает внутренняя. Без обратной
очерёдности движение читается как то же схлопывание, просто зеркальное.
Появление всегда мягче исчезновения — иначе окно «выстреливает».

### 9.3 Отмена

Анимации хранить в ref. При закрытии сессии, при повторном нажатии и при
размонтировании — `cancel()` на всех живых и удаление рамок. Каждый
`finished` обязан иметь `.catch(() => {})`: отменённая анимация
отклоняет промис.

При `prefers-reduced-motion: reduce` каскада нет вовсе — переключение
мгновенное, как сейчас.

**Воркеру не отдавать:** измерение и отмену.

## Этап 10 — повтор и автовоспроизведение

### 10.1 Где живут значения

`repeat ∈ {"off", "all", "one"}` и `autoplay ∈ {true, false}` — компоненты
кортежа состояния (И-J), но переживать закрытие сессии обязаны, а
состояние между сессиями `null`. Поэтому:

- значения хранятся в `signals/media.js` как обычные переменные модуля,
  сохраняются в `localStorage` (ключ `ugolok.media.prefs`);
- `openMedia` кладёт их в payload события `open`;
- `doOpen` переносит их в состояние;
- `setRepeat` / `setAutoplay` пишут и в состояние, и в хранилище.

Так δ остаётся чистой и не читает ничего снаружи.

### 10.2 Изменения в `media-machine.js`

Добавить в `EVENTS`: `"setRepeat"`, `"setAutoplay"`.

```js
function doOpen(state, payload) {
	const callActive = state?.callActive ?? false;
	const repeat = payload.repeat ?? "off";
	const autoplay = payload.autoplay ?? true;
	const play = callActive ? "suspended" : autoplay ? "playing" : "paused";
	return { cls: payload.cls, position: payload.position, display: "full", play, callActive, repeat, autoplay };
}

function doSetRepeat(state, payload) {
	if (state === null) return state;
	if (!["off", "all", "one"].includes(payload?.mode)) return state;
	return { ...state, repeat: payload.mode };
}

function doSetAutoplay(state, payload) {
	if (state === null) return state;
	return { ...state, autoplay: payload?.value === true };
}
```

Новая δ для `ended` (по-прежнему no-op при `cls === "image"` и при
`callActive`):

| `repeat` | есть следующий в классе | последний в классе |
|---|---|---|
| `off` | позиция +1, `play = "playing"` | `play = "paused"`, позиция на месте |
| `all` | позиция +1, `play = "playing"` | первый своего класса, `play = "playing"` |
| `one` | позиция на месте, `play = "playing"` | то же самое |

```js
function doEnded(state, payload, playlist) {
	if (state === null) return state;
	if (state.cls === "image") return state;
	if (state.callActive) return state;
	if (state.repeat === "one") return { ...state, play: "playing" };
	const p = stepInClass(playlist, state.position, +1);
	if (p !== -1) return { ...state, position: p, play: "playing" };
	if (state.repeat === "all") {
		const first = firstOfClass(playlist, state.cls);
		if (first !== -1) return { ...state, position: first, play: "playing" };
	}
	return { ...state, play: "paused" };
}
```

### 10.3 Кольцевой шаг для кнопок

При `repeat === "all"` кнопки «предыдущий»/«следующий» перестают
отключаться на краях. `stepInClass` не менять — он покрыт тестами и
используется в `doEnded` для честного «конца списка». Добавить в
`playlist.js` рядом:

```js
export function lastOfClass(pl, cls) { /* симметрично firstOfClass */ }
export function stepInClassRing(pl, position, delta) {
	const p = stepInClass(pl, position, delta);
	if (p !== -1) return p;
	const cls = pl.items[position].cls;
	return delta > 0 ? firstOfClass(pl, cls) : lastOfClass(pl, cls);
}
```

`doNext`/`doPrev` выбирают функцию по `state.repeat === "all"`.

### 10.4 Обязанность вида при `repeat === "one"`

Автомат при повторе трека **не меняет позицию** — значит вид не получает
повода перезапустить элемент. Перемотку делает он сам:

```jsx
onEnded={() => {
	const repeatOne = mediaSession.peek()?.repeat === "one";
	mediaEnded();
	if (repeatOne && elRef.current) {
		elRef.current.currentTime = 0;
		elRef.current.play().catch(() => {});
	}
}}
```

Читать `repeat` до вызова `mediaEnded()` — после него состояние уже новое.
`.catch` обязателен: политика автовоспроизведения браузера может отказать,
и тогда вид обязан сообщить об этом автомату через `mediaToggle()`, как
уже сделано для обычного отказа `play()`.

### 10.5 Кнопка

Три состояния на одной кнопке, как в большинстве плееров: выключено —
цвет `--muted`; весь список — цвет `--accent`; текущий — цвет `--accent`
плюс цифра «1» в углу. Без цифры `off` и `one` различались бы только
оттенком.

`aria-label` меняется вместе с режимом. Кнопка не рендерится при
`cls === "image"`.

### 10.6 Тесты

`tests/media-machine.test.js` и `tests/media-machine-exhaustive.test.js`
требуют правки: `stateKey` обязан включать `repeat` и `autoplay`, иначе
обход в ширину схлопнет различные состояния в одно и перестанет быть
исчерпывающим. Пространство вырастет в шесть раз — это ожидаемо и
приемлемо.

Новые проверки инвариантов в `checkInvariants`:
- при `cls === "image"` события `setRepeat`/`setAutoplay` не меняют
  наблюдаемого поведения (`ended` остаётся no-op);
- `repeat` после любого перехода принадлежит трём допустимым значениям;
- при `repeat === "one"` событие `ended` не меняет `position`;
- И2 не нарушается: `ended` при `callActive` не переводит в `playing`.

**Воркеру можно отдать:** 10.5 (кнопка и локали).
**Воркеру не отдавать:** 10.2–10.4, 10.6.

## Известный хвост, в эти этапы не входит

`allocWindow` строит окно владения по позициям в общем плейлисте, а лента
берёт соседей через `stepInClass` — по классу. В однородном чате это одно
и то же, в смешанном — нет; плюс при крупных фотографиях бюджет 16 МБ
режет окно до двух элементов. Боковой слайд при этом вызывает
`acquireMediaUrl` сам, но счётчика ссылок у него нет, и когда
`resourceOwner` отпустит этот digest, `releaseMediaUrlHandle` сделает
`URL.revokeObjectURL` под живым `<img>`. Проявится как битая картинка в
боковом слайде без видимой связи с жестом. Чинить отдельным этапом.
