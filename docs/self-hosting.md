# Свой relay + Blossom для локальной сети (AC-15)

«Уголок» развёртывается в **локальной сети**, не в публичном интернете —
relay (strfry) и файловое хранилище (Blossom) должны работать на машине
внутри вашей сети, к которой могут подключиться все клиенты. Это
руководство — для того, кто поднимает эту инфраструктуру (не обязательно
разработчик приложения), а не для тех, кто дорабатывает код клиента
(для этого — `docs/RUNBOOK.md`).

Поставка официального клиента (ветки, теги, канал `updates.*`) —
`docs/delivery.md`. Этот документ не про публичный интернет и не
заменяет LAN-путь `setup.sh` / `run.sh`.

Оценка времени: **strfry ~5-10 минут** (git clone + сборка из исходников)
+ **Blossom ~1-2 минуты** (Go build) + **~5 минут** на настройку bind-адреса
и первое подключение клиента — итого **15-20 минут** на типичной машине,
с запасом укладывается в порог AC-15 (< 30 минут).

## Что понадобится

| Что | Версия | Зачем |
| --- | --- | --- |
| ОС | macOS или Linux | оба скрипта поддерживают оба |
| Homebrew (macOS) | любая | ставит зависимости сборки strfry автоматически |
| Go | ≥ 1.26 | сборка Blossom-сервера (ставится `setup.sh`, если отсутствует) |
| C-компилятор | любой | нужен `mattn/go-sqlite3` (cgo); на macOS — Xcode Command Line Tools |
| Свободный IP:порт в сети | — | strfry слушает 7777/tcp, Blossom — 8080/tcp по умолчанию |

Проверить: `node -v` не нужен вовсе — сборка сервера не требует Node.js,
только исходники этого репозитория (скрипты) и системные инструменты
выше.

## 1. Получить скрипты

Файлы, которые нужны, лежат в `server/strfry/` и `server/blossom/`
этого репозитория — либо клонируйте весь репозиторий (`git clone`),
либо скопируйте только эти две директории на сервер.

## 2. Поднять relay (strfry)

```bash
server/strfry/setup.sh   # клонирует hoytech/strfry + собирает (~5-10 минут, один раз)
server/strfry/run.sh     # запускает relay
```

По умолчанию `strfry.conf` слушает **127.0.0.1:7777** (только локальная
машина) — для доступа из локальной сети измените в `server/strfry/
strfry.conf`:

```
relay.bind = "0.0.0.0"   # было "127.0.0.1" — слушать на всех интерфейсах
```

и убедитесь, что порт 7777/tcp открыт в файрволе для вашей подсети (не
для интернета — см. предупреждение ниже).

`relay.auth.enabled = true` (NIP-42) уже включён; `relay.writePolicy.
plugin` по умолчанию пуст (принимает любое событие от аутентифицированного
клиента) — если нужен реальный whitelist по pubkey (AC-14), используйте
`server/strfry/whitelist-plugin.mjs` + `whitelist-add.mjs <pubkey-hex>`
(уже готовые скрипты, `whitelist.json` — просто JSON-массив hex-pubkey;
значение по умолчанию `["*"]` означает "открыт для всех", замените на
конкретный список для закрытой сети).

По умолчанию whitelist открыт для всех — это LAN, не интернет. Не
выставляйте порт 7777 в публичную сеть с `["*"]`.

## 3. Поднять файловое хранилище (Blossom)

```bash
server/blossom/setup.sh   # ставит Go при необходимости + собирает (~1-2 минуты)
server/blossom/run.sh     # запускает сервер
```

По умолчанию слушает **127.0.0.1:8080** — для локальной сети измените
`api_addr` в `server/blossom/config.yml` на `0.0.0.0:8080`, аналогично
strfry.

## 4. Подключить клиентов "Уголок" к своему серверу

В приложении: **Профиль → Relay-серверы** (и отдельно **Blossom-серверы**)
— добавьте `ws://<IP-вашего-сервера>:7777` (для relay) и
`http://<IP-вашего-сервера>:8080` (для Blossom), затем нажмите
"Сделать активным". Приложение переподключится автоматически (полный
разрыв старого соединения и установление нового — без перезагрузки
страницы). Каждый клиент в сети выполняет этот шаг один раз; дальше
настройка сохраняется локально и синхронизируется между СВОИМИ
устройствами (настройка сохраняется на устройстве).

## Данные и остановка

- `server/strfry/strfry-db/` (LMDB) и `server/blossom/blossom-db/
  database.sqlite3` — здесь живут события и блобы. Резервное копирование
  — обычное копирование этих путей при остановленном сервере.
- Остановить — `Ctrl+C` в терминале, где запущен `run.sh` (оба скрипта
  запускают процесс на переднем плане; для продакшен-эксплуатации
  оберните в systemd/launchd unit по вкусу — вне рамок этого MVP).

## Важно: локальная сеть, не публичный интернет

Конфигурация из коробки (пустой `writePolicy`/`["*"]` whitelist, `ALLOW
ALL` у Blossom) рассчитана на доверенную локальную сеть. Выставлять эти
порты в публичный интернет без дополнительного harden'а (полноценный
pubkey-whitelist, TLS-терминация перед WebSocket, rate-limiting на
уровне сети) — вне поддерживаемого сценария текущей версии.
