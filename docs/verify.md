# Проверка целостности клиента (NF-18)

Мессенджер "Уголок" — весь клиент это один файл `index.html`
(плюс `service-worker.js`). Тот, кто раздаёт этот файл, теоретически
может подменить его и обойти всю клиентскую криптографию. Чтобы это
обнаружить, каждый релиз сопровождается:

- `SHA256SUMS` — SHA-256 хеш собранного `index.html`;
- `SHA256SUMS.asc` — GPG-подпись этого хеша ключом владельца проекта.

Ниже — как самостоятельно убедиться, что конкретная сборка
соответствует опубликованному исходному коду, и что сервер отдаёт
именно её.

## 1. Импортировать публичный GPG-ключ владельца

Ключ публикуется отдельно от репозитория (в описании релиза, на
личном сайте владельца и т.п. — не в самом репо, иначе подмена
репозитория подделает и "доверенный" ключ). Получив ключ (файл
`owner.asc` или ID на публичном keyserver):

```sh
gpg --import owner.asc
# либо, если известен только ID:
gpg --keyserver hkps://keys.openpgp.org --recv-keys <KEY_ID>
```

Сверьте отпечаток (fingerprint) ключа с тем, что владелец публиковал
через независимый канал (не тот же сайт, где лежит релиз) — это
единственное, что не даёт злоумышленнику подменить и ключ, и релиз
одновременно.

## 2. Собрать клиент из исходного кода самостоятельно

```sh
git clone <URL репозитория>
cd ugolok-2-project
git checkout <тег или коммит релиза>
npm ci                      # строго по package-lock.json — версии зависимостей зафиксированы
npm run build                # создаёт dist/index.html + dist/service-worker.js
```

Либо одной командой: `bash scripts/release-hash.sh` (сама выполнит
`npm ci` + `npm run build` + посчитает хеш; подписывать чужим ключом
вы не сможете — свою подпись эта команда сделает вашим собственным
GPG-ключом, если он есть, что для проверки не требуется — достаточно
самой сборки и `SHA256SUMS`, см. шаг 3).

## 3. Сравнить хеш своей сборки с опубликованным

Владелец публикует `SHA256SUMS` и `SHA256SUMS.asc` вместе с релизом.
Положите оба файла рядом с вашей собственной `dist/` (или пересчитайте
хеш и сравните текст вручную):

```sh
cd dist
shasum -a 256 -c SHA256SUMS
# или, если есть GNU coreutils:
sha256sum -c SHA256SUMS
```

Ожидаемый вывод: `index.html: OK`. Если вместо этого
`index.html: FAILED` — ваша сборка байт-в-байт отличается от
опубликованной; это повод разбираться (отличается версия Node.js,
не тот коммит, испорченный `package-lock.json`), а не игнорировать.

## 4. Проверить, что хеш подписан владельцем, а не кем-то ещё

```sh
gpg --verify dist/SHA256SUMS.asc dist/SHA256SUMS
```

Ожидаемый вывод содержит `Действительная подпись` ("Good signature")
и fingerprint, совпадающий с тем, что вы сверили на шаге 1. Если gpg
говорит `bad signature` — файл `SHA256SUMS` был подменён после
подписи, не доверяйте ему.

Строка `WARNING: The key's User ID is not certified with a trusted
signature!` рядом с "Действительная подпись" — это НЕ ошибка, а
стандартное поведение GPG для только что импортированного ключа
(вы ещё не отметили его как доверенный локально). Значение имеет
только совпадение fingerprint из шага 1, а не эта пометка о доверии.

## 5. Проверить, что РАЗВЁРНУТЫЙ клиент — именно эта сборка

Шаги 1–4 доказывают, что опубликованный хеш подписан владельцем и
соответствует исходному коду. Остаётся последнее звено: убедиться,
что сервер, который вы сейчас открываете в браузере, отдаёт именно
этот файл, а не что-то ещё:

```sh
curl -s https://<ваш-домен>/index.html | shasum -a 256
```

Полученный хеш должен побайтово совпасть с хешем из `SHA256SUMS`
(без имени файла — сравнивается только первое поле). Если не совпадает
— сервер отдаёт другую сборку, доверять клиенту в этом сеансе нельзя.

## Итог

Только когда пройдены ВСЕ пять шагов — вы можете быть уверены, что:
исходный код, который вы прочитали и которому доверяете → это именно
то, что было опубликовано владельцем (подпись) → это именно то, что
собирается детерминированно (воспроизводимая сборка) → это именно то,
что вам отдаёт сервер прямо сейчас (сверка развёрнутого файла).
Пропуск любого шага оставляет брешь: без шага 5 подмена возможна
на уровне хостинга; без шага 4 — подмена самого `SHA256SUMS`; без
шага 3 — вы просто доверяете хешу на слово; без шага 1 — доверяете
подписи неизвестно от кого.
