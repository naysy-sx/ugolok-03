# Участие

`main` всегда должен собираться. Подробности git — `docs/RUNBOOK.md`.

- Многокоммитная или рискованная работа — ветка и PR в `main`.
- Одношаговая зелёная правка (опечатка, док, мелкий фикс) — можно прямо в `main`.
- Не заводить долгоживущие ветки `test`, `prod`, `develop`. Окружения — не ветки.

Не коммитить: `dist/`, `dist-updates/`, `*-db/`, `.env`, ключи, `node_modules/`.

Перед сдачей:

```bash
npm test              # верхний уровень + harness fake-relay/ws-bridge
npm run build
# или всё сразу:
./scripts/ci-check.sh
```

Служебные заметки разработки (не вход для контрибьютора) лежат в ветке `process` того же репозитория. Ветка публичная — это не секрет. `.gitignore` на `main` не спасёт от случайного merge `process` → `main`.
